# Mirror dedupe v2: delete builder-stream transcript rows whose record JSON is in the sealed stream (#476)

## 1. System Overview

`ingest.DedupeMirrorOnce` (`internal/ingest/dedupe.go:387`) is a one-time
removal of ingest-mirror rows that duplicate a sealed `round_file`. The daemon
calls it at start (`cmd/relevo/main.go:2881`). It ran on the dev laptop on
2026-09-24 (kv `mirror-dedupe.v1`) and kept 149 rounds of builder-stream
transcript rows (`transcript.owner_kind = 'round'`), about 32k rows and 73 MB.

The cause is its rule. `planTranscript` (`dedupe.go:210`) deletes a round's rows
only when `transcriptRowsEqual` (`dedupe.go:337`) finds a re-derivation that
reproduces every row's `seq`, `record_json`, `rendered` **and** `ts`. The
planner measured the live database:

| rounds | what is true | this plan |
|---|---|---|
| 100 | every row's `record_json` is byte-for-byte a line of the round's sealed `NNN-builder.jsonl`; `rendered`/`ts` differ (the renderer changed since ingest) | delete |
| 27 | every row's `record_json` is a line of the sealed stream **after** the exact rewrite `relevo migrate` applied to the stream files at the relay→relevo rename (`internal/migrate/rewrite.go:88-93`, state and config roots). The mirror rows were never rewritten | delete |
| 21 | no `NNN-builder.jsonl`, only `NNN-builder.log` | keep |
| 2 | the mirror binding has no unique record | keep (already `Unmapped`) |

`rendered` and `ts` are derived from `record_json`, and `seq` from the line's
order, so a row whose `record_json` is a line of the sealed stream holds nothing
the stream doesn't.

This plan adds a second, looser proof, run only when the exact one fails, and
bumps the kv key to `mirror-dedupe.v2` so the pass runs once more on databases
where v1 already ran. The backup, the single transaction, the stats document and
`VACUUM` are unchanged. On a database where v1 never ran, v2 does both jobs in
one pass. Expected result on the dev laptop: 127 more rounds (31,749 rows)
removed, and the file shrinks from about 445 MB to about 360 MB.

**Out of scope:** the `showDB` fallback in `internal/relevo/show.go` (issue
#476, open question 2), planner transcripts, artifacts (their rule is
unchanged), and deleting old backups.

## 4. Interface Definitions & Component Contracts

**`func (r Roots) Prefixes() []Prefix`** (legacy)
- Returns `{OldState→NewState}` then `{OldConfig→NewConfig}`, in that order,
  the same pairs `migrate` builds at `internal/migrate/migrate.go:223-225`.
- A pair is left out when either side is empty or `Old == New`. The zero
  `Roots` returns an empty slice.

**`func RewriteJSON(data []byte, pairs []Prefix) []byte`** (legacy)
- For each pair in order, replaces every `"<Old>/` with `"<New>/`, then every
  `"<Old>"` with `"<New>"`. This is exactly the loop now at
  `internal/migrate/rewrite.go:89-93`, moved.
- Pure. It never modifies `data`, and with no pairs it returns `data`'s bytes
  unchanged.

**`func DedupeMirror(d *db.DB, renames []legacy.Prefix) (dedupePlan, error)`** (was `DedupeMirror(d)`)
- `renames` may be nil. Otherwise it behaves as today, plus the second proof
  below. Update its doc comment (`dedupe.go:95-105`) to state both proofs.

**`func DedupeMirrorOnce(d *db.DB, backupDir string, renames []legacy.Prefix, now time.Time) (DedupeStats, bool, error)`**
- Same contract as today (the numbered list at `dedupe.go:370-386`), with
  `mirror-dedupe.v1` replaced by `mirror-dedupe.v2` in the text. `renames` is
  passed through to `DedupeMirror`.

**`const dedupeKVKey = "mirror-dedupe.v2"`** (`dedupe.go:368`). Extend the
comment: v1 was the exact-derivation pass (#422); v2 adds the stream-lines proof
(#476). A v1 row is left in kv as history and does not stop v2.

**New unexported helper, `streamLinesCover`:**
`func streamLinesCover(d *db.DB, record db.Record, rd db.Round, rows []db.TranscriptRecord, renames []legacy.Prefix) (covered bool, renamed int, err error)`
- Reads `builderStreamPathBase(rd.Number)` for `record.ID` with `d.RoundFileGet`.
  A read error is returned wrapped as `dedupe: round file <name>/<base>: %w`,
  like `deriveTranscripts` does. Not found → `false, 0, nil`.
- Splits the body with `roundFileLines` (the same splitter; never a new one)
  into a set of line strings.
- For each row, in order:
  - an empty `RecordJSON` → `false, 0, nil`. Log-derived rows have no record
    JSON; this rule never vouches for them;
  - `RecordJSON` in the set → covered;
  - otherwise, when `renames` is non-empty, take
    `string(legacy.RewriteJSON([]byte(RecordJSON), renames))`. If it differs
    from `RecordJSON` and is in the set → covered, `renamed++`;
  - otherwise → `false, 0, nil`.
- All rows covered → `true, renamed, nil`.
- Precondition: `rows` is non-empty (the caller has already returned on zero
  rows).

## 5. High-Level Pseudocode

```
planTranscript(plan, d, b, record, rd, renames):        # dedupe.go:210, gains renames
    rows = d.Transcript(OwnerRound, rd.ID)                # unchanged
    if none: return
    for derived in deriveTranscripts(...):                # unchanged exact proof, tried first
        if transcriptRowsEqual(rows, derived): plan it (as today); return
    covered, renamed = streamLinesCover(d, record, rd, rows, renames)
    if covered:
        plan.transcriptOwners += rd.ID
        stats.TranscriptRoundsDeleted++ ; stats.TranscriptRowsDeleted += len(rows)
        stats.TranscriptRoundsByStreamLines++ ; stats.TranscriptRowsRenamed += renamed
        return
    stats.TranscriptRoundsKept++
```

`renames` is threaded `DedupeMirror → planBinding → planTranscript`. Add a
parameter to each; `planArtifacts` doesn't need it.

## 6. Error Handling Strategy

No new error kinds.
- A `RoundFileGet` failure inside `streamLinesCover` fails the plan, as
  `deriveTranscripts` does today. `DedupeMirrorOnce` returns it; the daemon logs
  "mirror dedupe skipped" and retries next start (unchanged).
- A `renameRoots` failure is not an error for the dedupe. It runs with no
  renames, so the 27 renamed rounds are kept, which is the safe direction.
