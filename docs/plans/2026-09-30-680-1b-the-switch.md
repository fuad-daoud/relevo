## 1. Behaviour and the cases (the contract)

**The opener rule.** A process that opens `<state root>/relevo.db` (`store.DefaultRoot()` + `relevo.db`) dials `relevo.sock` instead, except: the daemon (it opens directly; it *is* the owner), tests (direct by default), the hidden `RELEVO_DB_DIRECT=1`, `--check`/`--preflight` (which never open it through the owner at all), and any other path (e2e roots, serve's per-owner roots, `t.TempDir()` stores) which opens directly. A dialled handle takes its origin from the `welcome` frame, never from `installation.json`; a client never mints that file.

**Auto-start.** A dial to a missing or refusing socket starts the daemon: `systemctl --user start --no-block relevo` when the unit is installed, `launchctl kickstart` on macOS when the plist is installed, otherwise a detached `relevo daemon` in its own session (`Setsid`, stdin `/dev/null`, stdout+stderr appended to `<state root>/daemon.log`). Then it re-dials with backoff until the budget is spent (25–100 ms jittered steps, the `db.Tx` precedent). Concurrent starters are harmless: extra daemons lose the lock and exit. Auto-start is the only recovery for a dial: no fallback to opening the file.

**Budgets.** The dial budget is per dial call: 2 s for verbs and hooks, ~0.5 s for `status --line`. A failed open aborts the command (every failure path in `newRuntime`/`cmdStatus --line` returns before the next open), so a process makes at most one budget-length dial per failed command. A dial after the owner answers is a plain dial. The statusline prints **nothing** (no stdout, no stderr, exit 0) when its open cannot reach the owner; every other statusline failure keeps today's stderr line. `status --json` keeps today's empty-document contract.

**Reconnects.** The dial hook lives in the wire client, so a fresh pooled driver connection (a long-lived `mcp`/`wait`/`ui`/serve handle after an owner re-exec or crash) re-dials the same socket and auto-starts the owner the same way. A request already sent when the owner goes away still fails with the connection-lost error (0b amendment C) — that is the bounded drain window, not a regression.

**Peek.** `relevo daemon --check` and `--preflight` never dial, never auto-start, never route, and never open or mint a database beyond `loadConfigReadOnly`'s read-only open of an existing file (`db.OpenReadOnly`, closed at once — this open does not become a second client of the owner). They also stop running `captureAgyEnv` (today a `--check` with `ANTIGRAVITY_*` set opens and can migrate the database, which §10 forbids) and stop wiring deliverers (today `newDeliverers` opens the database under `--preflight` when one exists).

**`RELEVO_DB_DIRECT=1`.** Hidden: when set, the machine database opens directly, as today, and no socket is touched. Not in the usage text or the README; removed with the driver swap (#466, stage 2).

**The daemon holds one handle.** `cmdDaemon` opens one direct `*db.DB` under the lock and everything in the daemon — the config store, `rt.Store` (gates, claims, run log, daemon.json, release cache), the agy deliverer's creds store — borrows it (`store.NewShared`). Consequences, both intended: the daemon no longer dials itself anywhere, and the newer-schema branch becomes reachable — a daemon older than the file now starts and serves it with its own ingest paused, which is 1a amendment F and today unreachable (§7.1). Clients keep today's 2–3 owner connections per process (config, store, deliverer), all dialled; only the daemon is consolidated.

**`db.Tx`.** A `BEGIN`/`BEGIN IMMEDIATE` refused `restarting` (inspectable through the `driver.ErrBadConn` wrap 1a installed) closes the pinned `*sql.Conn`, takes a fresh one and retries inside the existing busy-retry window (`beginRetry`, 30 s default). The owner guarantees a `restarting` request never ran, so retrying `BEGIN` cannot double-apply anything; `COMMIT` is not retried (today's rule).

**Serve.** `relevo serve` and its admin verbs dial the local owner like any client (`openMachineDB`); `dist/relevo-serve.service` gains `Wants=relevo.service` and `After=relevo.service`. Serve's own auto-start stays the fallback (a daemon spawned by serve would live in serve's cgroup). Contabo's user `relevo.service` is a servers-repo deploy step the MasterMind runs — listed here, not done here.

**Surfaces.** `relevo doctor`'s `database` row names the route (`· via owner <sock>` or `· via file`), and the `owner` row's fix says any command starts a missing daemon; the README's database / running-the-daemon / serve sections state the one-opener rule and the auto-start.

## 6. Flags on the seed (points resolved, not guessed)

1. **The daemon's newer-schema branch is dead today.** Seeding `schema_version = 999` and running `relevo daemon` (verified at this base) exits `relevo: schema is newer than this relevo`: `newRuntime`→`buildRuntime`→`st.DB()` refuses before `cmdDaemon`'s `d.Newer()` branch. 2. **`db.Open` gets its first production caller** (the daemon, via `openDBDirect`), which the 0b probe already noted as missing.
3. **The Newer refusal stays in `store.dbForWrite`, not in the opener.** `relevo serve` tolerates a newer schema today (`loadServeConfig` warns and proceeds); moving the refusal into `openDB` would change that. The hook branch reproduces today's refusal for stores and leaves `openDB`'s callers alone.
4. **`DBIfExists` keeps its `os.Stat` rule.** Client and daemon share one filesystem, so "no `relevo.db`" stays a local stat; no existence endpoint is needed for 1b (the probe's requirement 11).
5. **`captureAgyEnv` and the peek's deliverers open/migrate the database today**; §10 says they must not. Rounds 1–2 remove both, which is why the peek's contract is stated in the plan rather than left implied.
6. **Two mechanisms, two proofs.** The e2e uses the existing test-only `db.SetOwnerHop` switch (product-level transparency); the cmd/relevo tests use the production opener against an in-process owner on the real socket path; neither substitutes for the other, and the plan says which covers what.
7. **The suite/CI constraint**: no cmd/relevo test may spawn a daemon, a harness or the network, so auto-start, the unit detection and the detach are pinned through the `daemonStarter`/pure-helper seams, and `make check` runs with the routing off by default (TestMain).
