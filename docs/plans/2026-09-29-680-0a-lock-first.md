## Behaviour

### A. Atomic mint (`internal/installation`)

`Load(root)` keeps its contract: an existing file is authoritative, a missing one is minted, a malformed one is an error (never re-stamp). Only `mint` changes:

- Write the JSON to a fresh temp file in the same directory (`os.CreateTemp(dir, FileName+".tmp-*")`, 0600), `Sync` it, close it, then `os.Link` it to `installation.json`, and remove the temp via one deferred cleanup. `Sync` is what makes "whole file" true after a crash, not just under scheduling.
- A concurrent loser's `os.Link` fails `EEXIST` and it `read`s the winner's file: every caller gets one id, and a reader sees only no file or the whole file. `os.Rename` is wrong — it clobbers the winner and each caller returns its own id (this is mutation A below).
- Cases: (a) many concurrent Loads on a fresh root — no error, one id, no temp residue, exactly one `installation.json`; (b) existing file — unchanged, no clobber; (c) crash between write and link — one stray `installation.json.tmp-*` may remain; `Load` ignores it, no sweeper is added; (d) a pre-existing partial file is still a decode error, as it must be.

### B. Lock-first daemon start (`cmd/relevo`)

New order in `cmdDaemon`:

1. flags — unchanged;
2. `--preflight` / `--check` — `newRuntimePeek()` exactly as today, same error mapping, same returns (early-return branch);
3. daemon path — `store.DefaultRoot()` → `userConfigRoot()` → `loadConfigReadOnly(root, <configDir>/relevo)`: the read-only config load `--preflight` makes (files, else an existing database read-only, else nothing). Its value is discarded: `newRuntime` reloads config from the database it imports into;
4. `store.New(root).AcquireDaemonLock()` — `ErrDaemonRunning` returns immediately; a fresh root gets no `relevo.db`, `-wal`, `-shm` or `installation.json`, only `.daemon.lock` (as today);
5. `newRuntime()` — unchanged, now under the lock: `openDB` mints a whole `installation.json` and opens/migrates `relevo.db`, then imports config files and builds the runtime with gates (its `st.DB()` mints/opens once more, as today);
6. today's daemon block (runtime fields, scope log, reaper, exe identity, config watcher) and today's post-lock body (`rt.DB` open, dedupe, compression, installation touch, `daemon.json`, roles, hooks, run/re-exec) — unchanged.

No socket, no dial, no serve change; every other verb and hook keeps opening directly. `daemonFlagSet` and its registry row untouched. The post-lock body, including the tolerant second `rt.DB` open and the re-exec path, is not reordered.

## Seed-vs-code notes

1. `openDB` loads/mints the installation **before** `db.OpenWith` because the id is the handle's `Origin` (`wire.go:224–233`). The seed's "open and migrate → `installation.Load`" therefore resolves to: both inside `openDB`, both now after the lock; the post-lock `installation.Load` at `daemon.go:259` (the installation touch) already exists and is unchanged. No `db` API change.
2. `run()` calls `captureAgyEnv()` before dispatch (`main.go:189` → `wire.go:105–123`), and that path opens/migrates and mints when `ANTIGRAVITY_*` is set — so "a losing daemon creates nothing" has this one hole on an agy host. It is outside daemon.go, outside this stage's decided scope, absent from the test (TestMain unsets `ANTIGRAVITY_*`), and stage 1b removes it. Report it; do not fix it here.
3. `--check` today also runs the daemon-start block, so it emits `INFO scopes=on` on stderr. After the early return it does not. Exit codes, stdout silence and the no-db rule are unchanged; the drop matches README:406 and `daemon.go`'s own "prints nothing" comment. State it in the report; do not add a line back to preserve noise.
4. On a steady-state machine the pre-lock load opens the database read-only (config files are imported and removed). That is exactly `--preflight`'s load; a root whose file cannot be opened read-only now fails before the lock instead of at the write open. The order is decided — add no fallback.

## Deleted behaviour

1. `mint`'s create-the-final-path-then-write sequence: the window in which a concurrent reader could decode a zero-length or partial `installation.json` is gone; a racing loser reads the winner's whole file.
2. The daemon's pre-lock `newRuntime()`: a start that opens, migrates and mints before `AcquireDaemonLock` is gone; a daemon that loses the lock creates no `relevo.db`, `-wal`, `-shm` or `installation.json`.
3. `--check`'s fall-through into the daemon-start block: it no longer resolves the reaper and the executable or emits the `scopes=` stderr line; it returns straight from the peek, as its contract and README already say.
4. Nothing else: no socket, no dial, no auto-start, no `serve`/verb/hook change, no flag or registry row, no post-lock pass reordered, and `--preflight`'s output and side-effect freedom untouched.

## Deliberately not done

- No `captureAgyEnv` change (note 2): it is a property of every verb, not of the daemon start; stage 1b removes it.
- No `db`/`store` API change: the mint fix lives in `internal/installation`, so CLI verbs, hooks and `store.dbForWrite` all inherit it.
- No test spawns a process, a harness or the network; both tests touch only temp roots.
- No README or spec edit, no coverage-baseline edit, no new lint/filesize exclusion.
