# CI trim: fewer, shorter jobs per run

## 1. System Overview

relevo is a public repo, so GitHub-hosted minutes are free; the real limits are
the free plan's concurrency caps (20 jobs, of which 5 macOS). Every CI run
today starts 4 `check` jobs (2 of them macOS) plus `cross-compile`, and each
`check` job runs the race-enabled test suite twice. With several builders
pushing at once the macOS jobs queue. This round changes one file,
`.github/workflows/ci.yml`, in three ways:

1. Delete the duplicate `race detector` step (`make check` already runs
   `go test -race -count=1 ./...`, Makefile line 18).
2. Cancel a PR's in-progress run when the PR is pushed again (never on `main`).
3. On `pull_request` events, drop the `macos-latest` x `go 1.25` matrix cell.
   PRs run 3 `check` jobs (1 macOS); pushes to `main` keep the full 4.

Nothing else changes: not `release.yml`, not the Makefile, not any script.

## 4. Interface Definitions & Component Contracts

The workflow's contract after this round:

| Event | `check` jobs | macOS jobs | superseded run |
|---|---|---|---|
| `pull_request` | ubuntu/1.25, ubuntu/stable, macos/stable | 1 | cancelled by the next push to the same PR |
| `push` to `main` | all 4 cells | 2 | never cancelled |

`cross-compile` runs unchanged on both events. `make check` stays the single
source of truth for what "check" means, and the race detector still runs in
every `check` job, once, via `make check`.

## 5. High-Level Pseudocode

The file is small, so the exact edits are given. These are the only edits
(line numbers are from `origin/main` f0b4c4bc).

**Edit A: add a top-level `concurrency` block** between `permissions:`
(lines 8-9) and `jobs:` (line 11):

```yaml
# A new push to a PR supersedes its running CI; main is never cancelled,
# so every commit that lands on main gets a complete run.
concurrency:
  group: ci-${{ github.event.pull_request.number || github.ref }}
  cancel-in-progress: ${{ github.event_name == 'pull_request' }}
```

**Edit B: exclude macOS x 1.25 on PRs.** In `jobs.check.strategy.matrix`
(lines 25-30), keep `os` and `go` as they are and add after `go:`:

```yaml
        # PRs skip macOS on the 1.25 floor to stay under the free plan's
        # 5-concurrent-macOS-job cap; main still runs the full matrix.
        exclude:
          - os: ${{ github.event_name == 'pull_request' && 'macos-latest' || 'none' }}
            go: '1.25'
```

On `push` the `os` value evaluates to `none`, which matches no cell, so
nothing is excluded.

**Edit C: delete the duplicate race step.** In `jobs.check.steps`, delete
exactly these two lines, which are the last step of the `check` job:

```yaml
      - name: race detector
        run: go test -race -count=1 ./...
```

Also delete the one blank line left between the `make check` step and
`portability:` if two blank lines end up there.

## 6. Error Handling Strategy

- If `actionlint` rejects the expression in the `exclude` entry, do not
  improvise another matrix form. Halt and report the exact actionlint output.
- If the PR run in step 4 does not show exactly the job set in section 4,
  halt and report the job list you saw.

## 7. Working Efficiently

Each model step costs a round trip, so:
- Make edits A, B and C to `ci.yml` in one edit call (or one Write of the
  whole file). Read the file once first.
- Run the checks together: `actionlint .github/workflows/ci.yml && make check`.
- The focused check is `actionlint .github/workflows/ci.yml`. The full check is
  `make check`. Run the full check once, at the end.

If any step is impossible as written or contradicts the code, stop and report.
Do not bend the plan to fit.

## 8. Ordered Implementation Steps

**Step 0: sync.** Run `git fetch origin && git merge --ff-only origin/main`
in the worktree. It must fast-forward to f0b4c4bc or later. If it can't
fast-forward, halt.

**Step 1: edit `.github/workflows/ci.yml`.** Apply edits A, B and C from
section 5. Verification: `git diff --stat` shows only
`.github/workflows/ci.yml`, and `grep -c 'race' .github/workflows/ci.yml`
finds no `go test -race` line.

**Step 2: lint.** Run `actionlint .github/workflows/ci.yml`. It must exit 0
with no output.

**Step 3: full check.** Run `make check`. It must pass. (It does not touch the
workflow. This confirms the tree is otherwise green.)

**Step 4: commit, push, open the PR, and verify the job set.**
- Copy this plan to `docs/plans/2026-09-25-ci-trim.md` in the worktree if it
  is not already there, and commit it with the change (one commit):
  `ci: one race run per job, cancel superseded PR runs, one macOS job on PRs`.
- Push the branch and open a PR against `main` with `gh pr create`. The body
  summarises section 4's table.
- Wait for the run to start. Then list its jobs with
  `gh run list --branch <branch> --limit 1 --json databaseId --jq '.[0].databaseId'`
  followed by `gh run view <id> --json jobs --jq '.jobs[].name'`.
  Verification: exactly `cross-compile`, `check (ubuntu-latest, go 1.25)`,
  `check (ubuntu-latest, go stable)` and `check (macos-latest, go stable)`.
  No `macos-latest, go 1.25`. Do not wait for the jobs to finish, and do not
  merge.

The report states the PR number, the job list from step 4, and the
`git diff --stat`.
