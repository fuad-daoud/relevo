## The MasterMind's decision on the halt

`TestCancelInterruptsARunningStatement` fails under Turso because tursogo v0.8.1
cannot interrupt a running statement. The MasterMind checked the v0.8.1 sources:
`Connection::interrupt` and `set_query_timeout` exist only in Turso's Rust API
(`sdk-kit/src/rsapi.rs:1177-1188`, `core/connection.rs:4829`). They are not in the C
ABI (`sdk-kit/turso.h`), not registered by tursogo (`bindings_db.go` registers no
interrupt function), and there is no pragma for them. **Accept the gap. Do not add
an interrupt through purego, and do not upgrade tursogo.**

What must hold instead:

1. **The client never waits on a statement it cancelled.** Today a cancelled
   client blocks until the owner replies (the test waited the full 5 s). Under
   Turso the owner cannot reply until the statement ends, so the statusline's
   500 ms budget and every verb budget would stretch to the statement's length.
   In `internal/db/wire/client`, on context cancellation the client sends the
   cancel and then returns `ctx.Err()` at once, after a bounded grace for the
   owner's reply (a small named constant; say why in one comment). From then on
   that session is unusable: its next use reports `driver.ErrBadConn` through
   `IsValid`/`ResetSession`, so `database/sql` discards it.
   **Hazard:** never return `driver.ErrBadConn` from the cancelled call itself.
   `database/sql` retries a pool `Exec` on `ErrBadConn`, and that already produced a
   duplicate INSERT once in this code base (the #680 review). The cancelled call
   returns `ctx.Err()`; only the session's *next* use is refused.
2. **The owner lets the statement finish, then discards that connection.** It
   must not serve that connection again, and must not leak it. Check what a drain
   (re-exec) does while such a statement runs: the drain window is bounded, so
   confirm the exec is not held past it, and say so in the report with the lines.
3. **Tests.**
   - Move `TestCancelInterruptsARunningStatement` unchanged into a
     `//go:build modernc` test file: modernc still interrupts.
   - Add a Turso twin (`//go:build !modernc`),
     `TestCancelReturnsToTheClientWhileTheEngineFinishes`: a cancelled heavy
     statement over the wire returns `context.Canceled` to the client within 1 s;
     a new query through the same `*DB` then succeeds on a fresh connection; once
     the statement ends, the owner's live-connection count returns to its
     baseline. Size the heavy statement so it ends within a few seconds under
     `-race`.
   - Add a both-tags test that the cancelled call is not retried: a cancelled

   - Mutations to run and report: remove the client's early return (the twin

4. **Docs.** In `docs/specs/2026-09-29-db-owner-design.md`, where cancellation is

### 1. Owner-mode: direct-only operations are an explicit, listed exception

The owner-mode proof, "the suite passes unchanged through the owner"
(`docs/plans/2026-09-29-680-0b-owner-protocol.md:208`), assumes every `DB`

and `engineCode` reads an engine's own error before it is put on the wire. A test
of a direct-only operation therefore opens a direct handle explicitly, in both
modes. That is a decided exception, not a bent test.

### 2. `TestOpenLeavesAnExistingFileAlone` is a product bug. Fix the product, not the test.

Under modernc, closing the last connection checkpoints the WAL. Under Turso, the
owner's handle leaves the marker in a 531 KB `-wal`. Find why the owner-side close
does not checkpoint the way a direct handle's `Close` does (your round-1
deviation #2), and make the owner's direct handle checkpoint on close exactly
like any direct handle. The test stays unchanged and must pass in both modes.
A daemon that stops without checkpointing leaves the next start a large WAL to
replay, and makes a file copy taken after shutdown incomplete.

### 3. Invalid UTF-8: repair on write in both engines; repair once on conversion

Your probe showed that Turso refuses to write invalid UTF-8 and cannot read it.
relevo stores harness output, which can hold invalid bytes.

- **On write, in both engines:** every `string` argument bound to a statement

  place in `internal/db`: the connector wrapper's `NamedValueChecker`, or the
  single place where arguments are bound. Do it under modernc too, so a file
  written after a downgrade stays readable by Turso. `[]byte` arguments are
  untouched: compressed columns are BLOBs.
- **On conversion:** add `repairInvalidText(conn)`, driver-neutral, run under
  modernc. For every table and every column declared `TEXT` (read the schema from
  `sqlite_master` and `PRAGMA table_info`), it rewrites values that are not valid
