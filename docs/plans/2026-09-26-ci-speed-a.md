# CI speed A: lint job, prebuilt linter, sharded race tests (2026-09-26)

## 1. System overview

The `ci` workflow (`.github/workflows/ci.yml`) takes a median of 6m23s on a PR and 7m10s on main. The critical path is
the `check (ubuntu-latest, go stable)` job:

| Part | Median |
|---|---|
| setup-go | 12s |
| `go install golangci-lint@v2.14.0`, which compiles about 100 modules from source | 48s |
| `make check` → `go vet` | 25s |
| `make check` → golangci-lint | 24s |
| `make check` → `go test -race -count=1 -cover ./...` | **292s** |
| everything else | ~10s |

Inside the test step, `internal/relevo` alone runs for 198s. Its 1,055 tests run one after another, and every other
package finishes while it is still going. The other legs (ubuntu go 1.25, macOS stable, and macOS 1.25 on main) take
5.5-6 minutes for the same reason.

This round makes three changes:

1. **Static checks move into their own `lint` job** that runs once, on ubuntu with go stable.
   - golangci-lint comes from its prebuilt release archive, with a checksum check, instead of `go install`.
   - Its analysis cache persists across runs.
2. **Every test leg is split into 3 shard jobs.** Each shard runs:
   - a third of the whole packages, and
   - a third of `internal/relevo`'s tests, selected by `-run`.
3. **A `coverage` job merges the shards' coverage** and runs the existing baseline guard, `scripts/check-coverage.sh`,
   on the merged result.

Local `make check` must behave exactly as it does today: the same checks, and the full unsharded test run.

The target is a PR critical path of about 3 minutes. The builder cannot run GitHub Actions. The planner measures the
result on the PR after the round.

## 3. Data structures

### 3.1 Shard assignment (the output of `test-shard.sh --dry-run`)

The output is line-oriented text on stdout, one record per line, sorted:

- `pkg <import path>`: a whole package this shard runs.
- `test <import path> <TestName>`: one test of a split package this shard runs.

Rules:
- **Split packages.** `SPLIT_PKGS` holds their import-path patterns, space-separated. The default is
  `./internal/relevo`, which resolves to `github.com/fuad-daoud/relevo/internal/relevo`.
- **Whole packages** are `go list ./...` minus the split packages, kept in `go list` order. Whole package number `i`
  (0-based) goes to shard `i mod TOTAL`.
- **Test names of a split package.**
  - Collect every name matched by `^func (Test[A-Z0-9_][A-Za-z0-9_]*|Example[A-Za-z0-9_]*|Fuzz[A-Za-z0-9_]*)\(`
    across the package directory's `*_test.go` files.
  - Exclude `TestMain`, then sort and de-duplicate with `LC_ALL=C sort -u`.
  - Test number `j` (0-based) goes to shard `j mod TOTAL`.
  - Reading source costs nothing, which is why names come from there. `go test -list` would compile the package once
    more.
- **The invariant:** for any TOTAL ≥ 1, the TOTAL shards are pairwise disjoint and their union is every whole package
  plus every test name of every split package.

### 3.2 Shard output directory (`OUTDIR`, default `.shard`)

| File | Content |
|---|---|
| `whole.txt` | stdout+stderr of the whole-package `go test`, in exactly the form `make check` writes to `.coverage.txt` (`ok  <pkg>  <time>  coverage: N% of statements`) |
| `split-<base>.txt` | stdout+stderr of the split package's `go test` for this shard, where `<base>` is the last path element (e.g. `relevo`) |
| `split-<base>.out` | that run's `-coverprofile`, in `mode: atomic` because `-race` forces it |

A shard that got no whole packages writes an empty `whole.txt`. A shard that got no tests of a split package writes
neither split file for it.

### 3.3 Merged coverage input

`scripts/cover-merge.sh` reads a directory tree that contains the shards' OUTDIRs (the downloaded artifacts). It writes
to stdout a file that `scripts/check-coverage.sh` parses without any change:

- **Whole packages:** every line of every `whole.txt`, verbatim.
- **Split packages:** for each `<base>`, exactly one synthesized line:
  `ok  <import path>  0.000s  coverage: <P>% of statements`.
  - `<P>` is computed from the union of all `split-<base>.out` profiles.
  - The `split-<base>.txt` lines are never copied, because each one reports a partial percentage.
- **How `<P>` is computed:**
  - A profile line has the form `<file>:<startLine>.<startCol>,<endLine>.<endCol> <numStmts> <count>`. Its block key
    is the text before the first space.
  - A block counts as covered when any profile reports `count > 0` for its key.
  - `P = 100 × Σ numStmts(covered blocks) / Σ numStmts(all blocks)`, over distinct keys, printed with one decimal
    (`%.1f`).
  - The `mode:` header lines are skipped.
  - This is the same arithmetic `go test -cover` uses, so an unsharded run and a merged sharded run agree for that
    package.
  - Only blocks whose file lives under the package's own import path count: the key's file part, minus its final
    `/<file>.go`, must equal the import path. A test binary's profile holds only that package's blocks, but the check
    stays anyway.

## 4. Interfaces and component contracts

### 4.1 `scripts/test-shard.sh`

```
Usage: test-shard.sh [--dry-run] INDEX TOTAL [OUTDIR]
  INDEX   0 <= INDEX < TOTAL
  TOTAL   >= 1
  OUTDIR  default .shard; created if missing, and existing files in it are overwritten
Env: SPLIT_PKGS (default ./internal/relevo)
Exit: 0 when every go test it ran passed, 1 when any failed, 2 on bad usage
```

- POSIX `sh`, `set -eu`, and clean under `shellcheck`. It is exercised on both GNU and BSD userlands, because macOS
  shard 0 runs `make check-scripts`. So: no `grep -P`, no GNU-only `sed -i`, and no `mapfile`.
- `--dry-run` prints §3.1 and runs no tests. It needs only `go list`, which works offline once the module cache is
  warm.
- In a normal run:
  - Whole packages: `go test -race -count=1 -cover <pkgs...> > OUTDIR/whole.txt 2>&1`.
  - Each split package, run concurrently with the whole-package command as a background job:
    `go test -race -count=1 -cover -coverprofile=OUTDIR/split-<base>.out -run '^(<names joined by |>)$' <pkg> >
    OUTDIR/split-<base>.txt 2>&1`.
  - Wait for every job, then `cat` every output file to stdout so the CI log shows it. Exit 1 if any job's status was
    non-zero.
- The `-race -count=1 -cover` flags are the same as `make check`'s. Keep them literally identical.

### 4.2 `scripts/cover-merge.sh`

```
Usage: cover-merge.sh DIR
  DIR   a directory searched recursively for whole.txt, split-*.txt and split-*.out
Output: §3.3 on stdout
Exit: 0; 1 when DIR holds no whole.txt at all, or when a split-<base>.out set is empty or unparsable
```

- POSIX `sh` plus `awk`, and clean under `shellcheck`.
- **The import path of a split package** is the `$2` of the `ok`/`FAIL`/`---` line that holds `coverage:` in any of
  its `split-<base>.txt` files. When that is missing, derive it from the profile's file keys (the key's file part
  minus `/<file>.go`).

### 4.3 Makefile targets

| Target | Runs, in this order |
|---|---|
| `check-static` | gofmt test; `go vet ./...`; `$(MAKE) lint`; check-comments; check-filesize; the mod-tidy block; check-plugin-version; check-name; `$(MAKE) check-scripts` |
| `check-scripts` | the shellcheck block; the `scripts/*_test.sh` loop |
| `check-test` | the `go test -race -count=1 -cover ./... > .coverage.txt` line; `sh scripts/check-coverage.sh` |
| `check` | `$(MAKE) check-static` then `$(MAKE) check-test` |

- Every recipe line moves verbatim from today's `check`. Only the grouping changes.
- Add the three new target names to the `.PHONY` line.
- `make check` still runs every check it runs today, once each.

### 4.4 `ci.yml` jobs

| Job | Runs on | When | Steps |
|---|---|---|---|
| `changes` | ubuntu | always | unchanged |
| `lint` | ubuntu-latest, go stable | `code == 'true'` | checkout; setup-go stable; shellcheck only if missing; install golangci-lint (§4.5); restore/save the lint cache (§4.5); `make check-static` with `RELEVO_REQUIRE_LINT=1`; then `CGO_ENABLED=0 GOOS=darwin go vet ./...` |
| `test` | matrix `os` × `go` × `shard: [0, 1, 2]` | `code == 'true'` | checkout; setup-go; `sh scripts/test-shard.sh ${{ matrix.shard }} 3 .shard`; on shard 0 only: install shellcheck (the existing per-OS step), then `make check-scripts`; on ubuntu-latest + stable only: upload `.shard/` as artifact `shard-${{ matrix.shard }}` (default `if:`, so only a passing shard uploads), `retention-days: 1` |
| `coverage` | ubuntu-latest, go stable | `code == 'true'`; `needs: [changes, test]` | checkout; setup-go stable; download every `shard-*` artifact into `shards/`; `sh scripts/cover-merge.sh shards > .coverage.txt`; `cat .coverage.txt`; `sh scripts/check-coverage.sh` with `RELEVO_REQUIRE_COVERAGE=1` |
| `cross-compile` | unchanged | unchanged | unchanged |

- **The `test` matrix** keeps today's `os`, `go`, `fail-fast: false`, `env.GOFLAGS` (and its comment), and the PR
  exclude of macOS/1.25, with its comment. Add `shard: [0, 1, 2]` and name the job
  `test (${{ matrix.os }}, go ${{ matrix.go }}, ${{ matrix.shard }}/3)`.
  - On main, the two macOS legs make 6 macOS jobs, one over the free plan's cap of 5 concurrent macOS jobs. One of
    them queues. Say that in the matrix comment. Main is never cancelled, so queueing only costs time.
- **The `coverage` job** reads artifacts from the ubuntu/stable legs only, so it must download only those.
  - Download with `pattern: shard-*`. Only the ubuntu/stable leg uploads, so the pattern matches exactly the 3
    artifacts.
  - `check-coverage.sh` compares `go env GOVERSION` against the baseline header. Both jobs use `go-version: stable`
    in the same run, so they resolve the same Go.
- **Drop the `install golangci-lint` step and the `RELEVO_REQUIRE_LINT` / `RELEVO_REQUIRE_COVERAGE` env from the test
  legs**, along with their now-stale comments. Carry the "CI has no network at test time, so the install is a setup
  step" reasoning into the lint job's install step comment.
- **Actions** keep today's major versions (`actions/checkout@v4`, `actions/setup-go@v5`). The new ones are
  `actions/upload-artifact@v4`, `actions/download-artifact@v4` and `actions/cache@v4`.

### 4.5 golangci-lint install and cache (lint job)

- **Install.** Download `golangci-lint-2.14.0-linux-amd64.tar.gz` and `golangci-lint-2.14.0-checksums.txt` from
  `https://github.com/golangci/golangci-lint/releases/download/v2.14.0/`.
  - Verify the archive with `sha256sum --check --ignore-missing` against the checksums file.
  - Extract the `golangci-lint` binary into `$(go env GOPATH)/bin` and append that directory to `$GITHUB_PATH`.
  - Keep the version in one job-level `env: GOLANGCI_LINT_VERSION: 2.14.0` and reference it from the URL and the
    cache key. Do not hardcode it a second time.
- **Cache.**
  - Set job env `GOLANGCI_LINT_CACHE: ${{ runner.temp }}/golangci-lint-cache`.
  - Use `actions/cache@v4` on that path with key
    `golangci-lint-${{ env.GOLANGCI_LINT_VERSION }}-${{ hashFiles('go.sum', '.golangci.yml') }}-${{ github.sha }}`
    and restore-keys `golangci-lint-${{ env.GOLANGCI_LINT_VERSION }}-${{ hashFiles('go.sum', '.golangci.yml') }}-`
    then `golangci-lint-${{ env.GOLANGCI_LINT_VERSION }}-`.
  - If `runner.temp` cannot be used in job-level `env`, use `${{ github.workspace }}/../golangci-lint-cache` or
    set it in a step with `$GITHUB_ENV`. Either is fine. Keep the cache outside the checkout, so gofmt, `git
    ls-files` and check-name never see it.

## 5. High-level pseudocode

```
test-shard.sh:
  parse args; validate INDEX/TOTAL (exit 2 on bad usage)
  module := go list -m
  split := resolve each SPLIT_PKGS pattern with go list
  whole := go list ./... minus split, in go list order
  mine_pkgs := whole[i] where i mod TOTAL == INDEX
  for each s in split:
    dir := go list -f '{{.Dir}}' s
    names := grep the §3.1 regex over dir/*_test.go, strip "func " and "(", drop TestMain, LC_ALL=C sort -u
    mine_tests[s] := names[j] where j mod TOTAL == INDEX
  if --dry-run: print "pkg ..." and "test ..." lines sorted; exit 0
  mkdir -p OUTDIR
  start: go test (whole, mine_pkgs) > whole.txt       [skip if mine_pkgs empty -> empty whole.txt]
  start: go test (split s, -run ^(names)$) > split-<base>.txt/.out   for each s with names
  wait each, record status; cat outputs; exit 1 if any failed

cover-merge.sh DIR:
  find whole.txt files -> cat them (none -> exit 1)
  for each distinct <base> among split-*.out:
    pkg := import path from split-<base>.txt coverage line, else from profile keys
    awk over all split-<base>.out: skip mode lines; per key remember numStmts and covered |= count>0
    print "ok  <pkg>  0.000s  coverage: <P>% of statements"
```

## 6. Error handling

- **A failing test in any shard fails that shard's job.** The `coverage` job then never runs because of its `needs`,
  so a red test is never reported as a coverage verdict.
- `test-shard.sh` exits 2 on bad usage, before running anything. `cover-merge.sh` exits 1 on an empty or unparsable
  input, and never prints a partial `.coverage.txt` with exit 0.
- **Missing coverage fails the job.** When the coverage job's artifact download finds nothing, `cover-merge.sh`
  exits 1, so the coverage guard is never skipped vacuously.
- `check-coverage.sh` is unchanged, including its `RELEVO_REQUIRE_COVERAGE` header-mismatch rule.

## 7. Deleted behaviour (closed list)

Everything not on this list survives.

1. `go vet ./...` no longer runs on the ubuntu/1.25, macOS/stable and macOS/1.25 legs.
   - The lint job's linux vet replaces it, plus its darwin cross-vet (`GOOS=darwin`).
   - `go test`'s built-in vet subset still runs on every leg.
2. The gofmt test, check-comments, check-filesize, the mod-tidy check, check-plugin-version and check-name run once,
   in the lint job, instead of on every leg.
   - Shellcheck and the `scripts/*_test.sh` tests still run on every OS × Go leg (shard 0), so the BSD userland on
     macOS keeps exercising the scripts.
3. The `go install golangci-lint` step is replaced by the checksum-verified download.

No test is removed.

## 8. Working efficiently

A model step costs a round trip no matter what it does, so:
- **Batch.** Read `.github/workflows/ci.yml`, `Makefile`, `scripts/check-coverage.sh`,
  `scripts/check-coverage_test.sh` (as the style model for the new `_test.sh` files) and `scripts/ci-code-changed.sh`
  in one parallel batch. Do not search for anything else. This plan names every location.
- **One write per file.** Write each new file in one call. Rewrite `ci.yml` in one Write.
- **Focused loop.** For every `.sh` file you add, run `shellcheck scripts/<f>.sh && sh scripts/<f>_test.sh`. Run
  `actionlint .github/workflows/ci.yml` (installed at `~/go/bin/actionlint`) after writing the workflow. Fix every
  finding before running again.
- **Final check, once.** Run `make check` in the foreground and wait for it. Never background it or end your turn
  while it runs.
- **Say so if gofmt checked nothing.** If `git ls-files` fails in the worktree (`.git` is a pointer file), the gofmt
  and check-name steps check nothing. Run `gofmt -l .` and say so in the report.

## 9. Ordered implementation steps

If a step is impossible as written or contradicts the code, stop and report instead of improvising.

**Step 1: split the Makefile's `check`** (§4.3).
- Deliverable: `check-static`, `check-scripts` and `check-test`, with `check` calling them.
- Verify:
  - `make -n check` lists the same commands as `make -n check` on the base commit, in the §4.3 order, plus the
    `$(MAKE)` lines.
  - `make check-scripts` passes.

**Step 2: `scripts/test-shard.sh` and `scripts/test-shard_test.sh`** (§3.1, §3.2, §4.1).
- The test runs `--dry-run` for TOTAL = 1, 2, 3, 4 and asserts:
  - no line appears in two shards;
  - the union of all shards equals the TOTAL=1 output;
  - the TOTAL=1 output lists more than 1,000 `test ... internal/relevo` lines and at least 30 `pkg` lines;
  - bad usage exits 2 (`test-shard.sh`, `test-shard.sh 3 3`, `test-shard.sh -1 2`).
- Verify:
  - the test passes and `shellcheck` is clean;
  - `sh scripts/test-shard.sh 2 3 "$TMPDIR/s2"` runs, passes, and writes `whole.txt`, `split-relevo.txt` and
    `split-relevo.out`;
  - report that shard's wall time (`time`).

**Step 3: `scripts/cover-merge.sh`, its test, and the fixtures** (§3.3, §4.2).
- Fixtures: two tiny hand-written shard dirs.
  - Each has a `whole.txt` with one `ok` line and a `split-relevo.out` over the same 4 blocks.
  - Choose `numStmts` and counts so the answer needs the union: shard A covers blocks 1-2, shard B covers blocks 2-3,
    and block 4 is never covered.
  - Include a `split-relevo.txt` whose coverage line carries the import path.
- The test asserts the exact expected output lines, and exit 1 on an empty dir.
- **Equivalence check, reported with both numbers.** Run it without `-race` to save time; the percentage does not
  depend on race.
  - Run `go test -count=1 -cover ./internal/relevo` and note its percentage.
  - Run the three shards' split commands with `-covermode=atomic -coverprofile` into three dirs, then run
    `cover-merge.sh` over them.
  - The two percentages must match to 0.1. If they do not, stop and report. Do not tune the arithmetic to fit.
