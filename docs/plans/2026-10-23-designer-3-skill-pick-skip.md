# Plan 3: The pick skips a candidate whose harness cannot see a required skill

**Prerequisite**: Plans 1 and 2 are already committed on this branch by the previous rounds (`skill.Resolve`, `Role.Skills`).

**Goal.** When relevo picks a candidate for an actor that needs a skill, a candidate whose harness cannot resolve it is skipped, and the pick line says why; if every candidate is skipped the pick fails with that reason; an explicitly named candidate that cannot see the skill is refused, so a designer round never starts without its skill.

**Behaviour and cases.**
- New gate kind `SkillMissing` (`"skill_missing"`), synthesised in memory, never written to the ledger (like `RolesMissing`). It carries `Role` (the actor), `Token` (the candidate's canonical ref) and a `Note` that is the whole reason: `skill design-runbooks not found for designer on claude: looked at <p1>, <p2>`. It renders as `skipped <name> (<note>)` in the pick line, in `allGated`'s error, and in `gatePart` / status wherever gates are listed; `GateKindText` says `skill missing`.
- A candidate is gated for an actor only when the registry says the actor serves it, the actor has effective skills, a directory is known, and `skill.Resolve` finds nothing for some required skill (one gate per missing skill). Several candidates sharing a kind each get their own gate.
- Unknown directory (a call site that has none) ⇒ no skill gates at all: relevo cannot judge, so it does not guess. Views (`relevo config`, `candidates`, the serve admin) do not show skill gates; `relevo doctor` is the place that does (Plan 2).
- Explicit pick (`--candidate x`): a `SkillMissing` gate for that actor and token is refused with the gate's note, exactly like `RolesMissing` (a spawned round would only die).
- A mid-round switch (`switchGates`) and a resumed bind apply the same gates for the binding's own directory.
- Judge what the runner will see, not the checkout the bind is issued from. A bind that creates a worktree runs the round in a fresh tree cut from the base commit, which carries only tracked files. For such a bind, a project-path match counts only when that path is tracked at the base commit (`git cat-file -e <base>:<repo-relative path>`); an untracked skill sitting in the main checkout does not satisfy it, and the note says `untracked in <repo>; commit it or install it per user`. User paths are checked on disk as usual. `skill.Resolve` already takes an `exists func(string) bool`, so this is a different `exists` passed in from `internal/relevo`, not a change to `internal/skill`.
- A bind on a server (`--server`) passes no directory: the server's home and tree are not visible from here, so no skill gates (the server's own pick judges its own disk when it spawns).

**Files touched (declared scope).**

- Edit: `internal/availability/ledger.go` (the `SkillMissing` kind constant and its comment), `internal/availability/gates.go` (`GateKindText`, `noteIsReason`; keep the file ≤600, it is at 584, so only these two small edits), `internal/relevo/candidate.go` (explicit-pick refusal next to the `RolesMissing` one at ~line 280), `internal/relevo/send.go` (the advisory preflight at ~line 454 and `dryRunGateNote` at ~line 888 treat `SkillMissing` as they treat `RolesMissing`), `internal/relevo/bind.go`, `add.go`, `builder_change.go`, `chain_start.go`, `inflight.go` (`switchGates`) only at the call sites that have a directory, replacing `availability.Gates(AvailabilityDeps(rt))` by the same call wrapped with the new `withSkillGates(rt, gates, dir)`, `README.md` (one paragraph under Plan 2's Skills paragraph), `docs/plans/2026-10-23-designer-3-skill-pick-skip.md`.

**Style reminders.** The tests are pure: build a `Runtime` with a registry, candidates and a fake `exists` func (add a small injectable seam in `skillgates.go`, for example a package-level default `os.Stat`-based checker held by `Runtime` or passed as a parameter; do not read the real disk in a test). No CLI test is added; if one is, it must not spawn a harness. Functions ≤70 lines; no history in comments.

**Steps.**

1. **Gate kind.** Add `SkillMissing` to `internal/availability/ledger.go`, extend `GateKindText` (`"skill missing"`) and `noteIsReason` (note is the whole reason). It is not a known ledger kind (`knownKind` stays unchanged). Verify: `go test ./internal/availability` with a test that `GateText(SkillMissing, zero, note)` equals the note and `GateKindText` is `skill missing`.
2. **Synthesis.** `internal/relevo/skillgates.go`: `skillGates(rt Runtime, dir string) []availability.Gate` over `rt.RoleRegistry()` roles with `Skills`, `rt.Candidates.Refs()` and `reg.Serves(role, ref)`, home from the user's home directory, `skill.Resolve` per required skill; and `withSkillGates(rt Runtime, gates []availability.Gate, dir string) []availability.Gate` appending them (returning `gates` unchanged when `dir == ""`). Note text as in Behaviour, listing every path looked at; a kind that is not `skill.Servable` gives `<kind> cannot load skills`. Verify: tests for: servable and present ⇒ no gate; absent ⇒ one gate with the exact note; present at the user path only ⇒ no gate; empty `dir` ⇒ no gates; an actor without skills ⇒ no gates; the gate's `Role` is the actor so another actor's pick ignores it (`gatesForRole`); for a worktree bind, a project-path skill present on disk but not tracked at the base ⇒ a gate whose note says untracked, and the same skill tracked at the base ⇒ no gate (fake the tracked check through the same injectable seam; no real git in the test).
3. **Pick behaviour.** Refuse an explicit pick of a `SkillMissing` candidate in `resolveRoleBase` (same `fmt.Errorf("%s: %s", c.Name, g.Note)` shape as `RolesMissing`), and make `send.go`'s advisory preflight and dry-run note treat it like `RolesMissing`. Tests through `resolveRole`: with two candidates, the first lacking the skill, the pick takes the second and `explainResolution` contains `skipped <first> (skill design-runbooks not found for designer on claude: looked at …)`; with both lacking it, the error wraps `ErrAllGated` and names the reason; naming the lacking candidate with `--candidate` is refused with the note; the same lacking candidate is picked normally for an actor without skills. Verify: `go test ./internal/relevo -run 'Skill|Pick|Resolve'`.
4. **Wire the call sites.** `grep -n 'availability.Gates(AvailabilityDeps(rt))' internal/relevo/*.go` and classify each: wrap with `withSkillGates` at a site that has the binding's directory (`bind.go` new bind: `opts.CWD`, with the tracked-at-base `exists` when the bind creates a worktree, and no directory when it binds on a server; `bind.go` resume: `b.CWD`; `add.go`; `builder_change.go`; `chain_start.go`; `inflight.go` `switchGates`: `b.CWD`); leave the sites without a directory alone (`runtime.go` reviewer pick, `placement.go`, `served.go`, `statsinputs.go`, serve and CLI views). List the classification in the report. Verify: `go build ./...` and the existing pick tests stay green.
5. **README** paragraph: a candidate whose harness cannot see a required skill is skipped with its reason, an explicit pick is refused, a worktree bind needs a project-local skill to be committed (an untracked one is reported as such), and a server bind is judged by the server. Verify the diff.
6. **Gate**: `make check-affected`. Verify exit 0.
7. **Save this plan** section verbatim to `docs/plans/2026-10-23-designer-3-skill-pick-skip.md` and commit it with the code (new commit; never amend).
