## 1. System Overview

The flow we want (user, 2026-09-26) is:

1. a planner actor writes a plan;
2. we review it;
3. we send it to the builder.

In commands:

```
relevo ask --name b --actor lite-planner -q "plan: <task>"      # or --file q.md
relevo show b --findings <id> > plan.md                          # review / edit
relevo send --name b --file plan.md
```

Two defects break it:

- **#593:** on a binding with no rounds yet, the findings command that `ask`
  prints (`relevo show b --round 1 --findings <id>`) fails. `showLive` and
  `showArchived` bound `--round` by the number of rounds that have a plan
  entry, but a consult is recorded on `b.Round`, the binding's current round,
  which may have no plan yet. The findings row itself is stored correctly.
- **#594:** without `--round`, `ask` requires `--file` and rejects `-q`.

`show` already prints the header to stderr and the text to stdout
(`cmd/relevo/show.go` ~251/267), so step 2 of the flow needs no new command.

## 4. Contracts

### `func findingsRound(requested, upper int, exists func(round int) (bool, error)) (int, error)` (unexported, `internal/relevo/show.go`)

A pure resolver, so it can be tested without a store.
- `upper` is the highest round a consult can be recorded on: the binding's
  current round counter (`b.Round` live, `ab.Binding.Round` archived), or the
  plan-round count if that is larger.
- `requested > 0`: when `1 <= requested <= upper` it returns `requested`,
  and the caller's read reports Missing when the file is absent. Otherwise it
  returns the existing error text `round %d: binding has %d rounds`, with `upper`.
- `requested == 0`: it scans `upper` down to 1 and returns the first round
  where `exists` is true. If none is found it returns `ErrNoFindings`. An
  `exists` error propagates.

### `showLive` (~129-185) and `showArchived` (~240-300)

- When `opts.Section == ShowFindings`, resolve the round with `findingsRound`
  **instead of** the current default and bound logic (the
  `round == 0 → completed` block and the `round > rounds` check). `exists`
  reads `rt.Store.FindingsPath(name, r, opts.FindingsID)` through the same
  reader the section uses, and a non-missing read means it exists.
- Every other section keeps today's logic exactly.
- `res.Round` is the resolved round. `res.Rounds` stays the plan-round count.
- Keep each function at 70 lines or fewer. If the new branch would push one over,
  move the branch into a helper shared by both.

### `func CheckAskInput(actor, file, question string, round int) error` (exported, `internal/relevo/ask.go`)

The one statement of `ask`'s flag rule. The CLI calls it, and it is testable
without a harness.
- Exactly one of `file` and `question` must be non-empty, whatever `round`
  is. The error texts:
  - with `round > 0`: `relevo ask --round needs --file or -q` (unchanged);
  - otherwise: `relevo ask needs --file PATH or -q QUESTION`.
- When `round == 0`, `actor` must be non-empty: `relevo ask needs --actor ACTOR` (unchanged).
- Check order: the actor first (when `round == 0`), then file/question.

### `Ask` (`internal/relevo/ask.go`)

- The non-round path (~94-99) currently does `os.ReadFile(opts.File)`. It must
  use the same body rule as the round path (~180-190): `body = []byte(opts.Question)`,
  or the file's bytes when `File` is set. Extract a small helper both paths call,
  `func askBody(file, question string) ([]byte, error)`, and keep the existing
  error wrapping `read question %s: %w`.
- The recorded ask file (`AskPath`) holds the body either way.

### `cmdAsk` (`cmd/relevo/ask.go` ~48-64)

- Replace both inline validation branches with one `relevo.CheckAskInput(*role, *file, *question, *round)` call.
- Keep the `--round ignores --actor` note, printed when `round > 0 && role != ""`.
- The `--question` help text (~line 33) becomes `the question itself; exactly one of --file and -q`.
