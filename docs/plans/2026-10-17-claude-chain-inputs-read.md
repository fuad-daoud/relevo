# Plan: fix #1259 -- a chain member on Claude at read/edit is refused its staged chain inputs

Saved verbatim as `docs/plans/2026-10-17-claude-chain-inputs-read.md` in the last step.

## Findings (checked against the code at main 016cb0a4)

- #1257 mechanism: `PromptFilePlaceholder` is appended to the claude permission args in `Harness.Launch` (`internal/harness/harness.go` ~345-349, only `h.Kind == "claude"` at `TierRead`/`TierEdit`). `Launch.PrintArgs` (~382-405) renders it as one element `--allowedTools=Read(/` + promptFile + `)` when `filepath.IsAbs(promptFile)`, else nothing. The value travels `PrintArgs(prompt, budget, dir, writableRoot, promptFile)` <- `spawn.HeadlessLaunch(..., writableRoot, promptFile)` and `Harness.ResumeBuild(..., writableRoot, promptFile)`.
- Callers that fill it: `internal/relevo/headless.go` startRound (~288) and resumeRound (~482), `internal/relevo/send.go` sendPreflight (~438, argv proof for dry run). Callers passing `""`: `internal/relevo/bind.go:822`, `internal/availability/probe.go:134`, `internal/consult/verify.go:287`.
- Chain staging is in one place. `chainSeedInput` (`internal/relevo/chain_seed.go` ~306) copies every binding round file a seed names to `Store.ChainInputPath(chain, src)` = `<root>/.chains/<chain>/inputs/<binding>-<NNN>/<file>` and names that copy; repo files go to `ChainRepoFilePath` = `.../inputs/repo/<rel>`; plan copies are `Store.ChainPlanPath` = `<root>/.chains/<chain>/plan-N.md`; task is `ChainTaskPath`. All of these sit under `Store.ChainDir(chain)` (`internal/store/paths.go` ~403-452). The one exception: a seed input that is a regular file the store reads as itself and is NOT a binding round file is named as it is (`chainSeedInput`'s `!roundFile && DiskRegularFile` branch). The builder checks which inputs can reach that branch (plan copies are in ChainDir; confirm nothing else lands outside it, and report if something does).
- Served chains need no special case: the server runs a chain with the owner's own `rt.Store` (`internal/serve/serve.go` `ownerStore`, `chains.go`), and `chainSeedInput`/`startRound`/`Admit` all use that `rt.Store`, so `rt.Store.ChainDir(c.Name)` is the right absolute path wherever the round starts. The served-start path goes through `startRound` (queue.go ~73) or a candidate switch; do not add a second code path.
- Chain membership lookup already exists in two forms: `tx.ChainByMember(name)` (inside startRound/resumeRound, a `*store.Tx` is in scope) and `rt.Store.ChainByMember(name)` (sendPreflight has no tx). `chainMemberBlock` (`internal/relevo/chain_send.go` ~166) already does exactly this tx-or-store split; copy that shape. `store.ErrNotFound` means "not a chain member".
- Rule syntax, confirmed against Claude Code permissions docs (context7, code.claude.com/docs/en/permissions): Read/Edit rules are gitignore patterns; `//path` is an absolute path from the filesystem root, e.g. `Read(//Users/alice/secrets/**)` matches `/Users/alice/secrets/**`. A rule via `--allowedTools` with a single leading `/` is cwd-relative, so the leading `//` is mandatory. So the rule is `"Read(/" + absChainDir + "/**)"`, the same `"Read(/"+abs` construction #1257 uses. A `Read` allow rule never grants Edit.
- `--allowedTools` is variadic; keep the `=` form, one argv element per rule (as #1257 does).
- Open question the builder MUST settle in the sandbox (step 7): whether two separate `--allowedTools=...` elements (prompt rule + chain-dir rule) both take effect, or the later one replaces the earlier. If they accumulate, keep one element per rule. If the later replaces the earlier, render both rules in ONE element (`--allowedTools=Read(//<prompt>),Read(//<chain>/**)` or whatever separator the real binary accepts) via PrintArgs. Do not ship until the sandbox shows both prompt-file Read and inputs Read succeed in the same run.
- agy: its prompt copy is #1258 (branch relevo/fix-1258, in flight) and does not cover chain inputs. Out of scope; follow-up below.

## Behaviour

1. Claude launch at tier `read` or `edit` for a binding that is a member of a chain gains one more argv element: `--allowedTools=Read(//<abs state root>/.chains/<chain>/**)`, placed immediately after the #1257 prompt-file rule and before candidate `extra_args`. It covers plan copies, task, `inputs/...` including `inputs/repo/...`. Read only; no Edit rule, `--add-dir` unchanged.
2. Any chain member, whatever its shape (reader or writer) and whatever the chain status: the seed of a correction builder may also name chain files. A binding in no chain, or any binding at `yolo`/`harness`, gets nothing new. codex/opencode/agy argv are byte-identical to today.
3. Empty or non-absolute value renders nothing (never `Read(//**)`); same rule as #1257.
4. Applies on every launch path of the round: fresh start (startRound), resume (resumeRound / `ResumeBuild`), and the send dry-run argv (sendPreflight), so `send --dry-run` shows the rule. Fresh `Harness.Resume` (consult/ask inline-prompt resume) is untouched.
