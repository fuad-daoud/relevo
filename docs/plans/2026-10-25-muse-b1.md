## Plan B1: owner socket dial failure from a harness sandbox

Behaviour: when the CLI cannot dial `relevo.sock` because the sandbox denies
the socket call (permission error, `EPERM`/`EACCES`, as muse's default sandbox
does), the verb fails with a new dedicated code and a next hint naming the
sandboxed shell (`muse --yolo` or `muse --disable-sandbox`; relevo's MCP
tools still work). A missing socket or a refused connection keeps today's
behaviour byte for byte (`relevo owner unavailable`, `internal`,
`relevo bugreport`).

Cases:

- First dial fails `EACCES`: new code, new hint, no bugreport line.
- First dial fails `EPERM`: same as `EACCES`.
- Socket missing (`ENOENT`) or refused (`ECONNREFUSED`): unchanged error,
  unchanged code, unchanged hint.
- Daemon genuinely starting (listener held or lock held): unchanged wait path.
- `status --line` on a sandboxed dial stays silent, as it is for an
  unreachable owner today.
- Human and `--json` envelopes both carry the new code and hint.

Seams:

- `cmd/relevo/machinedb_unix.go:24-27` (`dialUDS`: one plain unix dial; the
  `*net.OpError` wrapping `syscall.EACCES`/`EPERM` originates here),
  `cmd/relevo/machinedb_unix.go:82-112` (`dialWithStart`: retry loop that
  currently discards the first dial errno),
  `cmd/relevo/machinedb.go:186-215` (`openDBRoute`: wraps into
  `errOwnerUnavailable`), `cmd/relevo/machinedb.go:21` (sentinel),
  `cmd/relevo/args.go:255-360` (`writeError`: the one classifier; default arm
  is `codeInternal`), `cmd/relevo/clierror.go:14-42,54-82` (catalog; new row
  goes here), `cmd/relevo/status.go:284-294` (statusline silence arm).

Ordered steps:

1. Deliverable: a pure classifier for dial failures (e.g. in
   `cmd/relevo/machinedb_unix.go` or beside `errOwnerUnavailable`) reporting
   whether an error is a sandbox permission denial (`errors.Is` on
   `syscall.EACCES`/`EPERM`, plus `os.IsPermission` for wrapped forms) and
   never true for `ENOENT`/`ECONNREFUSED`/deadline errors. Works when a unit
   test feeds it synthesized `*net.OpError`/`*os.SyscallError` values with no
   socket and no daemon.
2. Deliverable: the first dial's permission errno preserved through
   `dialWithStart`'s retry loop and `openDBRoute` (sentinel or wrapped cause),
   so classification still sees it after the budget is spent; missing/refused
   paths unchanged. Works when `openDBRoute` against a permission-denied
   socket path returns an error matching the new sentinel while an
   `ENOENT` path still matches only `errOwnerUnavailable`.
3. Deliverable: one new catalog code in `cmd/relevo/clierror.go` with its exit
   and next hint (exit 1; hint names `muse --yolo`/`--disable-sandbox` and the
   working MCP tools), plus one `writeError` arm mapping the sentinel to it.
   Works when every existing `*_test.go` expectation on `internal` and
   `relevo bugreport` still passes unmodified.
4. Deliverable: unit tests in `cmd/relevo` (pure, no sockets, no spawned
   processes, per the CI rule that no `cmd/relevo` test spawns a harness):
   `EACCES` dial classifies to the new code with the sandbox hint and no
   `bugreport` next; `EPERM` likewise; `ENOENT` and `ECONNREFUSED` still
   classify `internal` with `relevo bugreport`. Works when breaking the
   `EACCES`/`EPERM` arm turns the pinning tests red (mutation check).
5. Deliverable: statusline arm in `cmd/relevo/status.go` treats the sandboxed
   error like `errOwnerUnavailable` (silence). Works when the existing
   statusline tests pass and a sandboxed-dial statusline test prints nothing.
