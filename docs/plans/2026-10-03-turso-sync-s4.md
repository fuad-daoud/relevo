# S4 builder-round plan — enable/disable with seed (spec §6 S4 only)

Base: spec tip `b3e861836` (`docs: turso cloud-sync design spec (#473)`). Plan only: no file changed in this round.

## 0. What S4 builds (§6 S4, §5, §7)

Enable preflight (origin gate with per-table counts, empty shared `secret`, compress pass done), the seed matrix (empty cloud → first push is the seed; existing local DB → documented Turso upload path then enable; new machine → `BootstrapIfEmpty` pull), the `relevo db sync enable|disable|status|push|pull` verbs with token via `--token-stdin`/env, and the exact §5 turn-off flow (best-effort bounded final push, mark disabled, delete token, close handle, local keeps working, cloud never deleted by relevo). Bounded: S4 ends with a user able to turn sync on late and off safely. S5 view and cockpit are out.

## 1. Seed-vs-code contradictions (said, not guessed around)

- **C1 — verbs do not exist.** The seed names `relevo db sync enable/dis/enable/disable/status/push/pull`. The code has exactly one `relevo db` subcommand: `query` (`cmd/relevo/db_query.go:22-31` usage, `:85-94` dispatcher; `cmd/relevo/main.go:71-74` usage text, `:252-253` dispatch). The builder creates the whole `sync` sub-dispatcher, its flag sets, and its owner-routed opens; nothing is extended in place.
- **C2 — origin gate covers 5 tables, backfill covers 2.** Spec §5 gate names `binding_record`, `binding`, `repo`, `mastermind`, `chains` (spec `:172-174`). `BackfillOriginOnce` stamps only `binding_record` + `binding` (`internal/db/origin.go:30-65`); `repo`/`mastermind` per-origin rows come from `UpsertRepo`/`UpsertMasterMind` scoping (`internal/db/origin_test.go:336-382`) with no backfill of old `''` rows, and `chains.origin` exists (`internal/db/migrations/016_chains.sql:15-18`) with no backfill at all. S4's gate must count all five tables directly (`SELECT COUNT(*) WHERE origin=''`) and must not widen `BackfillOriginOnce` (that would mutate history inside enable, which §5 forbids, spec `:175-176`).
- **C3 — S1/S2/S3 are assumed but absent.** No `relevo-local.db`, no second-file routing, no `SyncClient` interface, no `sync` config section, no `sync.*` kv markers exist in the tree (grep for `relevo-local|SyncClient|sync.*enable` hits only the spec). S4 names its seams against the S1-routing/S3-wiring base and, where the base differs, builds the minimal local-file-resident state it needs (local `sync` section in `config_doc`, `turso.token` in local `secret`, `sync.*` kv) without re-deciding S1/S2/S3.
- **C4 — `client.key` move belongs to S1.** Spec §5 moves the whole `secret` table into the local file in S1 (spec `:156-160`); the single-file code keeps secrets in `relevo.db` (`internal/db/config.go:98-157` secret surface; `internal/db/db.go:188-191` owner-only chmod rationale). S4's preflight asserts "shared `secret` is empty" against whichever handle S1 designates as shared, and in a pre-S1 tree asserts it against the S1 routing contract, failing closed with a named refusal until S1 lands.
- **C5 — `page_size` is never set.** The Turso upload path needs WAL + 4KB pages + `wal_checkpoint(TRUNCATE)` (issue body via spec §0, spec `:35-37`). The tree sets WAL per connection (`internal/db/engine_turso.go:90-97` `openPragmas`), checkpoints via `walCheckpoint` (`internal/db/compress.go:301-306`; `internal/db/vacuum.go:31-72` copy path), and reads `page_size` only in stats (`internal/db/stats.go:29-33`) — no `PRAGMA page_size=4096` anywhere. S4 must assert `journal_mode=wal AND page_size=4096 AND wal_is_empty` before the upload path, else write the seed copy with `VACUUM INTO` + pragmas (literal form per `internal/db/engine_turso.go:198-206` `vacuumIntoStmt`).
- **C6 — token plumbing is new.** `config secret` allows only `typesafe|client.key` (`cmd/relevo/config.go:31-33`, `:73-74` dispatch). `turso.token` plus `--token-stdin`/env intake is new surface owned by this slice, stored via the existing `Tx.SecretPut/SecretDelete` seam (`internal/db/config.go:126-139`).

## 3. Behaviour and cases

- **Preflight, each a named refusal naming the fix:** `TestEnableRefusesEmptyOrigin` (five per-table counts, points at `BackfillOriginOnce`/upgrade; spec §7 `:217-219`); `TestEnableRefusesSharedSecrets` (any row in shared `secret`, points at S1 split); `TestEnableRefusesCompressIncomplete` (no `zstd-compress.v1` kv row); `TestEnableRefusesAlreadyEnabled`; `TestEnableRefusesBadTokenSource` (`--token-stdin` empty + env absent, value never logged); `TestEnableRefusesUploadPrereqs` (non-WAL / non-4096 / non-drained WAL on the upload path).
- **Seed matrix (fake-backed, no network):** empty cloud → first `Push` is the seed; existing local DB → refusal prints the documented Turso upload path (WAL, 4KB pages, `wal_checkpoint(TRUNCATE)`) and enable proceeds only after the asserted seed copy; new machine (empty local shared file, non-empty cloud) → `BootstrapIfEmpty=true` open + `Pull`; `TestLateEnableSeedsOnce` (400 MB-class existing DB enables through the upload path with no rework/second conversion; spec §7 `:224-227`).
- **CLI verbs + token plumbing:** `db sync enable [--token-stdin | $TURSO_AUTH_TOKEN]`, `db sync disable`, `db sync status`, `db sync push`, `db sync pull`; token lands only in local `secret` as `turso.token` via `Tx.SecretPut`, never in logs/CDC/shared bytes (`TestTokenNeverLeavesMachine` shape per spec §4 acceptance, spec `:132-135`); `--token-stdin` beats env; neither present is a refusal.
- **Turn-off flow, exact §5 order (spec `:139-148`):** (1) one final push attempt, best-effort and bounded — failure does not block the rest; (2) mark disabled in the local `sync` section; (3) delete `turso.token` from local `secret`; (4) close the sync handle; local files keep full history and stay servable; cloud never deleted. Tests: `TestDisableKeepsLocalUsable` (reads/writes work after disable), `TestDisableFinalPushFailureStillDisables`, `TestReEnableIsFreshEnable` (re-enable runs full preflight + seed decision, never resumes), `TestDisableDeletesToken`.
- **Untouched:** S5 `:sync` view and cockpit surfaces; statusline tokens (§3, S2/S3); `BackfillOriginOnce` semantics; migration 015 no-backfill rule; any config-section sync (§2, S2).

## 4. Ordered steps (one line each: deliverable + how to know it worked)

1. **Origin-gate counter** (`internal/db`, new file beside `origin.go`): per-table `origin=''` counts over the five §5 tables — worked when `TestEnableRefusesEmptyOrigin` names all five counts on a fixture with one empty row per table.
2. **Preflight package** (gate + shared-secret-empty + compress-marker + already-enabled + token-source + upload-prereqs): one refusal per check — worked when each named refusal test fails before and passes after, with the fix named in the message.
3. **Seed-copy writer** (`VACUUM INTO` temp-dir + hard-link pattern per `internal/db/vacuum.go:27-72`, `walCheckpoint` per `internal/db/compress.go:301-306`): asserts WAL/4096/drained-WAL else writes the asserted copy — worked when `TestLateEnableSeedsOnce` and the upload-prereq refusal both pass, including the quote-in-path refusal from `vacuumIntoStmt`.
4. **`SyncClient` seam + fake** (only if S3's interface is absent at build time: `Push`/`Pull`/`Stats`/`Checkpoint` per spec `:192-194`, fake recording calls): constructor takes `TursoSyncDbConfig` with verified `BootstrapIfEmpty` default — worked when the seed-matrix tests drive the fake and assert open-config + call order.
5. **`db sync` dispatcher + verbs** (`cmd/relevo`, beside `db_query.go:85-94`): `enable/disable/status/push/pull` with `--token-stdin`/env and registry parity — worked when `db` parity/help tests and each verb's pure-path test pass with no network and no real-home reads.
6. **Enable path** (preflight → seed matrix → mark enabled → open handle): — worked when the seed-matrix tests (empty-cloud push-seed, upload-then-enable, `BootstrapIfEmpty` pull) pass against the fake.
7. **Turn-off path** (§5 four steps in order, bounded final push): — worked when `TestDisableKeepsLocalUsable`, `TestDisableFinalPushFailureStillDisables`, `TestDisableDeletesToken`, `TestReEnableIsFreshEnable` pass and each is broken by exactly one mutation.
8. **Docs + report**: spec-pointer comments only where the code cannot say why (no issue/spec numbers in code per CLAUDE.md `:67-70`); report quotes commands/outputs, commits + base SHA, mutations, and S5/cockpit as left-out.

## 6. What is deleted (closed list)

1. Nothing in the schema, the CLI surface, or stored history: no table, column, index, verb, or flag is removed by this slice.
2. At runtime only: the §5 turn-off deletes exactly the local `turso.token` secret row and the enabled mark; it never deletes local history rows and never deletes cloud data.
