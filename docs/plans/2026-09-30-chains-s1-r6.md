## Deliverable

`relevo chain --resume --name <n>` continues a halted or stopped chain; `relevo stop <n>` stops the
active member's open round and marks the chain stopped; `relevo done <n>` releases every member and
is refused while the chain runs.

## Pinned behaviour

**`ChainResume(ctx, rt, opts) (ChainResult, error)`** — `ResumeOptions{Name; Security *bool;
MaxCorrections *int; ReviewerActor, PlannerActor, SecurityActor string}`:

- Refuse a missing chain; refuse `running` (`chain <n> is running`) and `done` (`chain <n> is done`).
- Flags replace stored settings; flags not given keep them. Turning security on when the security
  member was never created creates it now (reader binding `<n>-sec`, the builder's tree, the security
  actor), through the same member helper round 4 used.
- Decide with the trace and the builder's log:
  - `newest` = the builder's newest closed round (max report-entry round);
  - `last` = the newest `builder_closed` event round in `chain_event`;
  - `newest > last` → review that round: build the reviewer seed for `newest`, step reviewing,
    awaiting the reviewer;
  - otherwise re-run the step that halted or was stopped: `building` → send plan `ch.Plan`;
    `reviewing` → seed the reviewer for the builder's last round; `correcting` → seed the correction
    planner; `scanning` → seed security; `planning-fixes` → seed the fixes planner.
- Always reset `corrections` for the current plan to 0, because a human has looked at it.
- Persist status running + the action's awaiting and write one trace row (`event=resumed`, action =
  the send/review, in the same `ChainSaveWithEvent` transaction); perform the send with
  `sendChainRound` (5a).
- A stopped builder round may have left edits: the re-sent plan runs on the tree as it is, as any
  round does. No cleanup.
- Pure decision helper `resumeStep(ch db.ChainRow, lastEventRound, newestBuilderRound int) chain.Seed`
  (or the plan-only variant), table-tested without I/O.

**`ChainStop(ctx, rt, name) (StopResult, error)`**:

- A chain that is not running returns `ErrNothingToStop` (the `relevo stop` "nothing to stop" answer,
  exit 0).
- Otherwise stop the awaited member with the ordinary `Stop` (stop.go:74): its stopped close raises
  the `stopped` event, which marks the chain stopped and queues the one end delivery (5a).
- If that member has nothing to stop (its round already closed but unreconciled), stop the chain
  directly under the lock: status stopped, one trace row (`event=stopped`, `action=stop`, reason
  `no open member round`), one end delivery.

**`ChainDone(ctx, rt, name) (DoneResult, error)`**:

- Refuse `running` with a conflict naming `relevo stop <n> first`.
- Call `Done` (done.go:27) for every member that exists, builder first; a member's failure returns
  the error and leaves the chain's status unchanged (retryable).
- Then mark the chain `done` with one trace row. No MasterMind delivery for this verb: the human ran
  it.

## Carry-overs from round 5b's review (do these first)

1. **A halted builder never repairs inside a chain.** The gate runs on the done marker whatever the report
   says, so today a builder that reports `halted`/`blocked`/`unstructured` with a red gate gets a repair
   round, where the design says the chain halts ("builder halted on plan i"). Guard both sides with the
   report outcome: in `chainApply`'s builder branch (`internal/relevo/chain.go`), take the repair path only
   when the outcome is `done`; in `markerClose`'s chain-member branch (`internal/relevo/headless.go`), call
   `startRepairRound` only when the outcome is `done` and `repairDecision` allows it. Non-members keep
   today's behaviour byte for byte. Test `TestChainBuilderHaltedWithRedGateHaltsTheChain`: a halted report
   plus a failing gate record and budget left -> no repair round opens, the chain is halted with
   `builder halted on plan 1: <note>`, one end delivery. It must fail when the `chainApply` outcome guard is
   removed; run that mutation and say so.
2. **The end delivery survives a gone builder.** `chainTerminal` stamps the end entry on `c.Builder`; when the
   builder record is the one that is gone, no delivery is ever queued and the MasterMind is never told.
   Queue it on the first member whose record exists, in the order builder, reviewer, planner, security; if
   none exists, halt the row anyway and log it. `WaitChain` (`internal/relevo/chain_wait.go`) must find the
   entry on whichever member holds it, in the same order. Tests
   `TestChainHaltWithTheBuilderGoneDeliversOnASurvivingMember` and
   `TestWaitChainFindsTheEndDeliveryOnASurvivingMember`.

`internal/relevo/{chain,headless,chain_wait}.go` join this round's scope for these two fixes only.
