## Pinned behaviour

- Choreography, per served builder round: the client ticks (the pending step ships); the test completes the served round (`finishRound`-style writes: report, commit, marker, runner dead); the server ticks to close it and start the gate; the test completes the gate with its scripted exit; the server ticks to close the gate and the round; the client ticks to collect and advance.
- The gate's real exit travels: round 1's gate exits non-zero → `chainApply` stages the chain's repair round and writes no trace row and no event (the chain waits again on the same member); round 2's gate exits zero → the reviewer is seeded. A red close that wrote a trace row, or a repair that never reached the server, must fail the test.
- The seed path #779 built is pinned end to end: the reviewer's prompt names `PlanDiffPath(builder, round)` (`Plan diff, every round of this plan so far: …`), the cumulative patch row is non-empty and spans the plan-start commit (plan 1 = the branch's cut commit) to the pulled result commit, and the round's own prompt is named when the round ran the planner's plan.
- The correction plan reaches the remote builder: the builder's staged prompt for round 3 is byte-identical to the planner's plan artifact, and the server's staged plan for that round is the same text (the pending step shipped it), with the chain's step note on the prompt entry.
- The client's `relevo/<name>` branch is at the last pulled result commit, and the binding's `RoundClosedTree` equals it.
- The trace: one row per transition, in seq order, ending at finish; the red close has no row. Exactly one `KindChain` end delivery exists at the end and `WaitChain` returns it once.
- Every wait is bounded and names the step it waited for (as `tickUntilChainFinishes` does), so a stuck chain fails with its row and its members' notes.

## Mutation checks

1. Treat the remote gate result as green on the client (drop the record the catch-up passes) → the first close reads `none` and no repair runs: the test must fail.
2. Skip the pending-send step in the daemon → the chain stalls awaiting round 1: the test must fail.
3. Ship the plan copy instead of the planner's plan for the correction → the round-3 staged prompt assertion must fail.
4. Do not record the pulled closed tree → the cumulative plan diff is absent from the reviewer's seed (or the diff runs from an empty start): the test must fail.
