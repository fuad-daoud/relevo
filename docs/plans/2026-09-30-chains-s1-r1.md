## Exact shapes

```go
type Status string   // running | halted | stopped | done
type Phase string    // build | security | finished
type Step string     // building | reviewing | correcting | scanning | planning-fixes
type Verdict string  // pass | changes | "" (none)

type Settings struct { MaxCorrections int; ReviewerActor, PlannerActor, SecurityActor string; Security bool }
type Awaiting struct { Member string; Round int }
type State struct {
    Status Status; Reason string
    Phase Phase; Step Step
    Plan, Plans, Corrections int
    Awaiting Awaiting
    Settings Settings
}

type EventKind string // builder_closed | reviewer_closed | planner_closed | security_closed | needs_you | stopped
type Event struct {
    Kind EventKind
    Member string; Round int
    Outcome string // builder: reporttail outcome
    Gate string    // builder: "green" | "red"
    Verdict Verdict
    PlanPresent bool // planner: artifact present and non-empty
    Findings int; FindingsGiven bool // security
    Reason string
}

type ActionKind string // "" | send | halt | stop | finish
type SeedKind string   // reviewer | correction | security | fixes
type Action struct { Kind ActionKind; Member string; Seed SeedKind; Reason string }

func Next(s State, e Event) (State, Action)
func ParseVerdict(body []byte) Verdict
func ParseFindings(body []byte) (int, bool)

type SeedView struct {
    Plan, Plans, Corrections int
    PlanPath, ReportPath, DiffPath, GateLogPath, GateResult string
    OutputPath, BranchDiffPath string
    Branch, Base string
}
func Seed(kind SeedKind, v SeedView) (string, error)
```

Contracts:

- An event whose `(Member, Round)` is not `Awaiting` is ignored: state unchanged, `Action{}`. An event
  in a terminal status is ignored the same way. (A replayed close can never advance twice.)
- `Next` never invents a round: a send action names the member and seed only; the caller fills
  `Awaiting.Round` from the member binding it sends. A persisted `Awaiting.Round` is never 0.
- Builder close, outcome done, gate green **or** red after regate → seed the reviewer, step reviewing.
  Outcome halted/blocked/unstructured → halt. The caller passes the report's note in
  `Event.Reason`; `Next` composes the exact §4.3 wording, `builder halted on plan <i>: <note>`, and
  `TestNextBuilderHaltedHalts` pins that string.
- Reviewing: pass + `Plan < Plans` → send plan i+1 to the builder, corrections 0, step building.
  pass + last plan + security on + phase build → seed security, step scanning, phase security.
  pass + last plan + (security off or phase security) → finish.
  changes + `Corrections < K` → seed correction to the planner, step correcting (corrections not yet
  incremented). changes + `Corrections == K` → halt. no/unparseable verdict → halt.
- Correcting: plan present → send the correction to the builder, corrections++, step building;
  missing or empty → halt. Planning-fixes: present → send to the builder, corrections 0, step
  building, phase stays security; missing → halt.
- Scanning: findings 0 → finish; > 0 → seed fixes to the planner, step planning-fixes; no count →
  halt.
- needs_you → halt with the member's reason; stopped → stop (status stopped).
- `ParseVerdict` reads the **last** fenced `relevo` block via `reporttail.FindRelevoBlock` +
  `SplitFenceLines` + `StripComment` + `UnquoteScalar`; accepts exactly `pass` and `changes`. A missing
  block, a missing key or an unknown value is "no verdict" — never a pass. `ParseFindings` accepts
  `findings: <n>` with n >= 0, and only that.
- Seed templates end with the block the member must end its output with (verdict block for the
  reviewer, finding-count block for security) and name every input by path; no file content is
  inlined.

## Mutation checks (design §12)

- Make `changes` advance to the next plan → `TestNextReviewerChangesSeedsCorrection` fails.
- Make `awaiting` match any round → `TestNextIgnoresAnotherRound` fails.
- Count a missing verdict as a pass → `TestParseVerdictRejectsMissingBlock` fails.

  report the missing datum instead of adding a callback.
