## 1. System overview

With several bindings running, read verbs (`relevo status`, `show`, `wait`)
failed with `state lock still held after 1m30s` and
`db: open ...: migrate: open failed: begin migration 001_initial.sql: busy`.
Two causes are in the packages this round owns:

1. **Every read takes the global state flock.** `Store.Load`, `List`,
   `ReadLog`, `ReadLogAfter`, `FindByCWD`, `PendingForPlanner`
   (`internal/store/store.go` ~335-410, `internal/store/log.go` ~214-265) all
   run inside `WithLock` (`store.go` ~898-945), the same exclusive flock the
   daemon holds across a whole reconcile of a binding -- including remote
   network calls. A read waits behind all of it. The binding record lives in
   SQLite, which already gives a reader a consistent snapshot; the flock only
   matters for (a) load-modify-save sequences and (b) the legacy-file import
   that `load`/`list` run first (`importPresent` / `importAll`,
   `internal/store/db.go` ~83-255), which writes.
2. **Opening an up-to-date database takes a write lock.** `db.Open`
   (`internal/db/db.go` ~66-119) calls `applyMigrations` unconditionally, and
   `applyOneMigration` (`internal/db/migrate.go` ~130-180) runs
   `BEGIN IMMEDIATE` for every embedded migration even when it is already
   recorded -- so any process opening the database queues behind the
   daemon's writer and fails on busy after `busy_timeout` (5 s).
3. **The WAL file never shrinks.** No `journal_size_limit` is set, so after a
   burst of writes the `-wal` file keeps its high-water size (~400 MB on the
   owner's machine).

Changes:
- A: `db.Open` skips `applyMigrations` when `have == know`.
- B: the read-only Store methods run without the flock when there is nothing
  to import; they take the lock exactly as today when a legacy file is
  present.
- C: `journal_size_limit` = 64 MiB in the DSN.

Out of scope: the remote sync and mirror paths (another round); any change to
write paths or `WithLock` itself; explicit checkpoints.

## 3. Contracts

```
// internal/db/db.go
const journalSizeLimit = 64 << 20   // bytes; the -wal file is truncated to this after a checkpoint resets it
DSN: existing pragmas + "&_pragma=journal_size_limit(<journalSizeLimit>)"
Open: after computing have and know:
  have >  know  -> newer (unchanged)
  have == know  -> return &DB{...} without calling applyMigrations   (NEW)
  have <  know  -> applyMigrations, re-read have (unchanged)

// internal/store/db.go
legacyPresent(name string) (bool, error)
  true when any of bindingPath(name), logPath(name), ViewedPath(name) exists
  -- exactly the three files importPresent adopts (read importPresent and
  mirror its conditions; if it adopts anything else, include that too).
  A stat error other than not-exist is returned.
anyLegacyPresent() (bool, error)
  true when importAll would import something: any non-dot directory under
  root whose legacyPresent(dirName) is true. Root missing -> false, nil.
  (importAll only triggers on bind.json today; checking all three files is
  deliberately a superset -- it can only make a read take the lock more
  often, never skip an import.)

// internal/store/store.go
(s *Store) read(name string, fn func(tx *Tx) error) error
  if legacyPresent(name) is true or errors: return s.WithLock(fn)
  else: return fn(&Tx{s: s})           // no flock, no s.mu
(s *Store) readAll(fn func(tx *Tx) error) error
  same, with anyLegacyPresent()
```

Callers switched (bodies otherwise unchanged):
- `Store.Load(name)`        -> `s.read(name, ...)`
- `Store.List()`            -> `s.readAll(...)`
- `Store.FindByCWD(cwd)`    -> `s.readAll(...)`
- `Store.ReadLog(name)`, `Store.ReadLogAfter(name, after)`,
  `Store.PendingForPlanner(name)` -> `s.read(name, ...)`

Before switching each, read the `Tx` method it calls and everything that
method calls: if any of them writes (to the database or to disk) other than
through `importPresent`/`importAll`, do not switch that method -- leave it on
`WithLock` and list it in the report. The unlocked path must be read-only.

Why skipping `s.mu` is safe: `dbForWrite` opens the handle under `sync.Once`,
and `*sql.DB` is safe for concurrent use.

## 6. Error handling

- `legacyPresent`/`anyLegacyPresent` stat errors other than not-exist are
  returned by `read`/`readAll` unchanged -- never silently treated as
  "absent", which could skip an import.
- An unlocked reader may see a binding saved a moment later by the daemon on
  its next call; that is the same staleness a locked `Load` already has once
  it returns.
