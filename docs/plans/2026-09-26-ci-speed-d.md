# CI speed D: the three slow single tests (2026-09-26)

## 1. System overview

Three tests spend their time waiting rather than testing. The planner confirmed each cause on `origin/main`:

| Test | Time | Confirmed cause |
|---|---|---|
| `internal/ui` `TestGoldenViews` (cases `cand-edit-132`, `cand-edit-invalid-132`) | 29s, the same with and without `-race` | The helper `drain()` (`internal/ui/split_test.go:58`) runs every returned `tea.Cmd` synchronously. Every keystroke in a focused `textinput` returns `cursor.(*Model).BlinkCmd` (bubbles v0.20 `cursor/cursor.go:161-183`), which blocks about 530ms on a timer. A goroutine dump taken mid-test showed `drain` parked in `BlinkCmd.func1`. |
| `internal/config` `TestImportTxFailureKeepsFiles` (`internal/config/config_test.go`, about line 275) | 30.5s | It holds a write transaction and expects `ImportFiles` to fail with `db.ErrBusy`. `db.(*DB).tx` (`internal/db/db.go`, about lines 215-240) retries a busy `BEGIN IMMEDIATE` for `beginRetryFor = 30s` (`db.go:38`), and each attempt also waits the `busy_timeout` of 5000ms (`db.go:35`). |
| `internal/store` `TestSaveWithLogWritesNothingWhenAnEntryFails` (`internal/store/log_test.go`, about lines 135-190) | 9s under `-race`, 1.0s without | It seeds `maxLogEntries-1` (9,999) log entries through SQLite to sit one entry below the cap. |

The planner also tried the UI fix in a scratch tree: every `textinput.New()` in `internal/ui` given a static cursor.
- `TestGoldenViews` fell from about 29s to 0.28s, and the whole `internal/ui` package from about 28.5s to 1.07s
  without race.
- All goldens passed unchanged.

**Goal.** Remove the three waits and change no assertion's meaning.
- The two `internal/ui` and `internal/db` seams are set only by tests, and production behaviour stays identical.
- The store cap becomes per-`Store`, with the same default.

## 3. Data structures

- **`internal/ui`:** `var staticCursor bool`.
  - Its doc comment explains why it exists: tests set it, because a blinking cursor's timer command blocks about half
    a second per keystroke when a test runs commands synchronously.
  - It is written only by `TestMain`, before `m.Run`.
- **`internal/db`:**

```
type Options struct {
    BusyTimeout time.Duration // per-connection busy_timeout; 0 = the default (busyTimeoutMS)
    BeginRetry  time.Duration // how long Tx retries a busy BEGIN IMMEDIATE; 0 = the default (beginRetryFor)
}
```

  - `DB` gains a `beginRetry time.Duration` field, resolved when the DB opens. The zero option becomes the package
    default, so after open the field is never 0.
- **`internal/store`:** `Store` gains `logCap int`. 0 means `maxLogEntries`. Only tests set it; it is unexported.

## 4. Interfaces and contracts

- **`func newTextInput() textinput.Model`** (in `internal/ui`) returns `textinput.New()`. When `staticCursor` is true,
  it first calls `in.Cursor.SetMode(cursor.CursorStatic)`.
  - Every `textinput.New()` in `internal/ui` (not `dash`) is replaced by it, including the one in
    `view_log_test.go`.
  - Postcondition: in production (`staticCursor` false) the input is byte-for-byte what `textinput.New()` returned
    before.
- **`func OpenWith(path string, o Options) (*DB, error)`** is `Open`'s body with `o` applied.
  - The DSN's `busy_timeout` comes from `o.BusyTimeout` in milliseconds, or `busyTimeoutMS` when it is zero.
  - `beginRetry` comes from `o.BeginRetry`, or `beginRetryFor` when it is zero.
  - `Open(path)` becomes `return OpenWith(path, Options{})`. Keep the existing `Open`/`open` split: `open` takes the
    options.
  - The template seeding (`seedFromTemplate`) stays the first statement of `open`.
- **`tx`** compares against `d.beginRetry` instead of `beginRetryFor`. The package vars stay, because
  `internal/db/db_test.go` sets them and those tests must keep passing unchanged.
- **`func (s *Store) maxLog() int`** returns `s.logCap` if it is above 0, else `maxLogEntries`.
  - `saveWithLog` and `appendLog` use it.
  - `decodeLog`, a free function over legacy files, keeps the constant.
  - `TestReadLogRefusesOversizedLogInsteadOfTruncating` is untouched.

## 5. Test changes (assertions keep their meaning)

- **`TestImportTxFailureKeepsFiles`:**
  - Build its store from `db.OpenWith(<tempdir>/relevo.db, db.Options{BusyTimeout: 20 * time.Millisecond,
    BeginRetry: time.Millisecond})`, then `Open(d)` with a `t.Cleanup` close.
  - Everything else is unchanged: the held `s.db.Tx`, `errors.Is(err, db.ErrBusy)`, and the files-kept checks.
  - Use a local helper in that test, or an `openStoreWith(t, db.Options)` helper beside `openStore`. `openStore`
    itself keeps using `db.Open`.
- **`TestOpenWithShortBusyFailsFast`** (new, in `internal/db/db_test.go`):
  - `OpenWith` a temp path with `{BusyTimeout: 20ms, BeginRetry: 1ms}` and hold `d.Tx` in one goroutine.
  - A second `d.Tx` must return an error wrapping `ErrBusy` within 2 seconds.
  - It must not call `t.Parallel()` and must not touch the package vars.
- **`TestSaveWithLogWritesNothingWhenAnEntryFails`:**
  - Set `s.logCap = 5` right after `seedBinding`.
  - Replace every `maxLogEntries` in the test with `s.maxLog()`. The seed loop writes `s.maxLog()-1` lines, and the
    counts compare against `s.maxLog()-1`.
  - The assertions are otherwise unchanged.

## 7. Error handling

- `OpenWith` returns the same errors as `Open`.
- A negative option is treated as 0, meaning the default. Say so in the `Options` doc.

- **Batch.** Read these in one parallel batch. Nothing else needs reading.
