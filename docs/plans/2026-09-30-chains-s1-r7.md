# Chains slice 1 · round 7 — `show --trace` and `wait` on a chain

One-shot builder round. It starts from a branch where rounds 1-5a and 8 are merged, and runs in parallel
with round 5b (repair before the reviewer, the member sweep) on another builder; round 6 (`--resume`,
`stop`/`done` on a chain) is NOT on this branch. The MasterMind merges the branches afterwards, and the
slice lands as one PR. Commit, never amend. Ends with `make check` green.

## Deliverable

`relevo show <n> --trace` renders the ordered `chain_event` trace (and `--json` prints one document);
`relevo wait --name <n>` returns when the chain finishes (exit 0) or halts or is stopped (exit 3),
with the one end delivery as output. `show <n> --round R` without `--trace` keeps reading the builder
binding, and `wait` on any other name is untouched.

## Exact shapes

```go
// internal/relevo/chain_trace.go
type ChainTraceDoc struct {
    Name, Status, Phase, Step string
    Plan, Plans, Corrections  int
    Events []ChainTraceEvent  `json:"events"`
}
type ChainTraceEvent struct {
    Seq int; TS time.Time; Phase, Step, Member string; Round int
    Event chain.Event; Action chain.Action; Reason string
}
func ChainTrace(ctx context.Context, rt Runtime, name string) (ChainTraceDoc, error)
func RenderTrace(doc ChainTraceDoc) string // one line per event, in seq order
```

- `Show` returns the text through `ShowResult{Text: RenderTrace(doc), Live: true, Section: ShowTrace}`
  so `printShow`'s JSON path works; the JSON document is `ChainTraceDoc` encoded by the CLI.
- Trace line shape (design §9.1): `plan 2/4  build    x r3       check red after regate` — plan i/N,
  the phase and step **before** the event, the member and its round, then the event's detail
  (`check green` / `check red after regate` / `pass` / `changes` / `no verdict` / `correction plan` /
  `1 finding` / ...). The renderer maps `chain.Event`/`chain.Action` kinds to those words; a halt
  appends its reason.

```go
// internal/relevo/chain_wait.go
func WaitChain(ctx context.Context, rt Runtime, name string, timeout, interval time.Duration, peek bool) (WaitResult, error)
```

- Loads the chain; if absent, return `store.ErrNotFound` wrapped (the CLI's binding_not_found path).
- Polls every `interval` until status != running or `timeout` (the existing `WaitTimeout` code).
- Finished -> `Code 0`; halted and stopped -> `Code 3` (reuse `WaitNeedsYou`'s value or name a
  `WaitChainStopped = 3`; the `wait` registry row already declares exit 3).
- `Line` = `chain <n>: <status> · plan i/N · k corrections` (halt adds the reason).
- Payload, unless `peek`: `delivery.PullPendingThrough(rt.Store, ch.Builder, "wait", 0)` — the one
  end entry queued by 5a; empty when it was already pushed. `--peek` leaves it pending.
