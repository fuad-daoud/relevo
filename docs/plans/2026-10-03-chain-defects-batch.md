## Behaviour and cases

**#864 — resume converts a pre-workflow row instead of failing.** A chain row with empty `WorkflowJSON` (created before custom chains, never converted) currently fails `chain --resume` with `internal: chain <n> carries no workflow` from `chainWorkflowDef` (`internal/relevo/chain_engine.go:21-23`). After the fix, the local resume path converts the row through the existing pure conversion (`chainConvertLegacy`, `internal/relevo/chain_convert.go:106-127`) and resumes normally. Cases: halted legacy row with legacy columns + member bindings converts and resumes; a row that cannot convert keeps today's failure (halted with the conversion reason, no silent drop); an already-converted row is byte-identical through the new path (conversion is skipped when `WorkflowJSON` is present). Server-chain mirrors are out of scope: the server converts, the client never fabricates a workflow.

**#769 — `stop` ends a halted round (decision: stop, not `--candidate`).** Either recovery path from the issue is enough; the plan picks `stop` because it is one code path, it matches local behaviour, and the `--candidate` half is already partially done (see contradiction 3). After the fix, the server's `handleStop` performs the stop on a halted binding exactly as for a running one (kill/reap/gone close, halt cleared, round closed) instead of answering `409 round_halted`. Cases: halted remote binding with a dead process stops to a closed round and a subsequent `send`/`send --candidate` starts clean; halted binding whose process is somehow still alive is killed like any open round; idle/closed bindings still answer `409 nothing_to_stop`; a `send` (plain or `--candidate`) against a halted binding still answers `409 round_halted` — send never ends a halt, stop does. `candidateSendRefused` is unchanged (the served+NEEDS YOU exemption stays). The client's `CodeRoundHalted` mapping in `stop.go:110-111`, the send-path `409 round_halted` in `serve/rounds.go:303-321`, and the `remote_send.go:132-155` guards stay as old-server compat. The builder verifies no chain semantics change: stopping a server-chain member out from under a running chain must behave exactly as stopping a running member does today (name the guard it checked: `serverChainMember` in `stop.go:134` and whatever refuses direct member stops on chained bindings).

**#847 — reproduce first, then fix deliver-vs-retry, else halt the item.** The predicate state: a member's current round has a `NNN-done` and/or `NNN-report.md` on disk while the round is NOT open in the log (no prompt entry, or a report entry already present), so `sendChainRound` (`internal/relevo/chain_send.go:54-59`) returns `ErrReportPending` and the chain halts via `chainFlowSendText` (`internal/relevo/chain_engine.go:186-191`) on the ordinary advance, or via `chainResumeRunAction` (`internal/relevo/chain_resume_wf.go:271-284`) on resume. The naive fix (await the round's close) hangs: per `headless.go:704` the reconcile takes its idle branch when the round is not open, so no close is coming. The builder first builds that state with fakes and confirms the halt; then captures live state (member log entries around the round, file mtimes vs `HaltAt`/`RoundStartedAt`, process liveness, whether the log ever opened the round) and implements exactly one of: deliver the on-disk output as the round's close, or discard the stale files and resend — whichever the captured state justifies, with the choice and its evidence in the report. If the predicate state cannot be constructed into a halt, the builder commits no fix, writes the analysis (which candidate cause the evidence rules out), and stops that item.
