## Behaviour and cases

- Within one tick, the first fetch failure against a server marks that server failed for the rest of the tick; every remaining binding naming that server makes zero network calls that tick and reconciles against a no-op fetch (binding left as-is apart from the first failure's own unreachable stamp/status). Failure means `fetchRemote` returned with `Err != nil` (covers `GetBinding` unreachable/auth/cert/unknown-server and catch-up aborts); success clears the mark only for that tick (the map is per-tick, not carried).
- Across ticks, a server whose prefetch failed backs off: the next tick makes zero dials to that server until the backoff expires, then tries exactly one binding again to probe recovery. A successful probe ends the backoff; a failed probe re-arms it. Backoff lives on `Daemon` (process state like `releaseRetryAt`/`ingestSeen`), reads an injectable clock following the existing `syncNow`/`syncClock` pattern, and never suppresses local bindings or other servers.
- The dial is bounded in seconds, not 30 s, on the prefetch path: transport-level `DialContext` timeout plus `ResponseHeaderTimeout` (both single-digit seconds, builder picks exact values) plus a short per-prefetch context deadline so the first failure is bounded even with the client's 4-attempt retry. Non-prefetch callers keep their existing retry/deadline semantics; they inherit only the transport floor, which covers headers, never bodies, so large downloads are unaffected.
- DONE bindings make zero prefetch dials; archived bindings never reach `Tick` (existing `List` behaviour, pinned, no new code). Paused keeps today's skip. Unknown-state and newer-format bindings keep today's skip-before-fetch.
- Prefetch stays inline in the binding loop (no new goroutine per server). The fetch still runs unlocked before the state lock (`tickOne` at `daemon.go:415-418`), and the skip check runs before the dial, also unlocked.
- A tick whose server never answers still completes local work and post-loop phases within a fixed bound (seconds): exactly one bounded dial to the dead server per backoff window, all other dead-server bindings skipped, local binding reconciled and persisted, `Tick` returns nil. The test uses a blocking fake `RemoteClient` honouring `ctx.Done` and injected timeouts/fake clock, never real 30 s waits, and lives in `internal/relevo`, never `cmd/relevo`.
- `SyncRemote` (`remote_sync.go:515-580`, the CLI read path) is out of scope and keeps today's serial behaviour; it must not share the tick's per-tick skip map. If the builder finds a one-line helper reuse, it says so in the report; otherwise it leaves `SyncRemote` untouched.
