# Plan: #911 — remove the dead delivery/state kinds (or document why each stays)

One builder round. Three items, each closed by removal or by a comment
explaining why it stays. Reviewer judges whether each "stays" is earned.

## Base and branch

Base on the `origin/main` tip at round start; the builder records the actual
base SHA in its report. New branch, new commits only, never amend or rebase.
Save this plan as `docs/plans/2026-10-03-ev911-dead-kinds.md` in the first
commit.

## Behaviour and cases

1. **`store.KindQuestion`** (`internal/store/log.go:37`). Nothing writes a
   question entry; readers in `view/waiting.go:57`, `view/statusline.go:222,
   299,543`, `view/status.go:367`, `ui/fleet_group.go:99`, `ui/fetch.go:243`.
   Remove the readers' question branches (they are unreachable) and either
   remove the kind or keep it solely as a tolerant decode value for old
   records. If any reader's branch turns out reachable (a writer exists the
   issue missed), that item flips to "document why it stays" with the writer
   named.
2. **The `HELD` display state.** `view.DisplayState` never produces it;
   readers in `view/sort.go:12`, `view/statusline.go:283`, `ui/styles.go:70`,
   `ui/view_fleet.go:107`, `ui/fleet_group.go:31`. Same treatment: remove
   the dead branches, keep decoding tolerant.
3. **`Binding.StaleNotifiedAt`** (`internal/store/binding.go:257`). Only
   ever cleared (`bind.go:460`, `remote_send.go:258`, `reconcile.go:718`,
   `send.go:706`). Remove the field and its clears if nothing reads it;
   JSON decoding of old records must stay tolerant (missing field already
   decodes fine — the builder verifies with an old-shape fixture, not by
   argument).

No behaviour change: `make check` plus the focused suites for
`internal/store`, `internal/view`, `internal/relevo`, `internal/ui` must
be green before and after, and the report names the suites.

## Ordered steps

1. Branch from `origin/main` tip, record SHA, commit this plan doc.
   Done when `git log --oneline -1` shows the base and status is clean.
2. Reachability audit: for each of the three items, grep every writer and
   confirm the issue's "no writers" claim (or name the missed writer and
   flip that item to document). Done when the report lists writers per
   item (empty or named).
3. Removal (or documenting comments), one item per commit, one mutation
   per item (restore one deleted branch → the focused suite still passes,
   proving no test covered it; the mutation evidence is the point).
   Done when focused suites are green.
4. Full verification: `make check` and `sh scripts/check-comments.sh`
   green. Done when the report quotes the commands and outputs.

Constraints on all steps: no harness spawn, no network; no `#NNN` in code
or comments; new commits only.

## Deleted behaviour

Unreachable branches only. If step 2 finds a live writer, nothing for that
item is deleted.

## Report must include

Commits with SHAs and the recorded base SHA; the writer audit per item;
each mutation and what it showed; focused suite + `make check` /
`check-comments.sh` outputs; anything deliberately left (with the reason).
