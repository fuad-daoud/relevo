# Plan: #929 — one scope rule in every status format, default this MasterMind, plus --all

One builder round. Decision (made by the owner, on the issue): `--json`
and `--line` stay scoped (agents and the statusline read them); the human
output matches them; `--all` recovers the fleet view with a footer hint.

## Base and branch

Base on the `origin/main` tip at round start; the builder records the actual
base SHA in its report. New branch, new commits only, never amend or rebase.
Save this plan as `docs/plans/2026-10-03-ev929-scope.md` in the first
commit.

## Behaviour and cases

After the fix, all three formats (`relevo status`, `--json`, `--line`)
show the same scope by default: this MasterMind's bindings. A new `--all`
flag shows every MasterMind's bindings in all three formats. When the
default view hides other MasterMinds' bindings, the human output carries a
one-line footer: `<N> bindings belong to other MasterMinds:
relevo status --all` (exact count; absent when zero).

The builder first enumerates the divergence: where the human path resolves
scope (machine-scoped today) vs where `--json`/`--line` resolve it
(MasterMind-scoped, empty when identity is ambiguous — cf. the
two-OpenCode-sessions `RELEVO_MASTERMIND` resolution gap noted on the
issue), and unifies them on the MasterMind-scoped rule. The ambiguous-
identity case must refuse or scope explicitly, never silently show another
scope in one format and none in another.

Cases: single-MasterMind repo → all formats agree, no footer; multi-
MasterMind repo default → each MasterMind sees only its own in every
format, human shows the footer with the exact count; `--all` → every
format shows everything; ambiguous identity → explicit refusal in every
format (no format disagrees with another).

## Seams

- Status verbs (`cmd/relevo` status paths) and `internal/relevo/status.go`
  `Status`/`buildReport`/`statusRow` (scope resolution + `--all` flag +
  footer; builder names the exact functions).
- MasterMind identity resolution (the `RELEVO_MASTERMIND` / multi-session
  path — read-only unless the refusal needs it).
- Deliberately untouched: serve-side status, chain rows, `--name` single-
  binding path (keeps working under both scopes).

## Ordered steps

1. Branch from `origin/main` tip, record SHA, commit this plan doc.
   Done when `git log --oneline -1` shows the base and status is clean.
2. Repro tests first: two MasterMinds, one binding each — human shows both
   while `--json` shows one (today's divergence, asserted); `--all` absent
   (flag does not exist). Done when the divergence test fails exactly on
   the format disagreement.
3. Fix: unified scope + `--all` + footer. Mutations: drop the footer count
   source → footer test fails; revert one format to machine scope → its
   agreement test fails. Done when the focused suites are green and each
   mutation fails exactly its named test.
4. Full verification: focused suites for every touched package, then
   `make check` and `sh scripts/check-comments.sh` green. Done when the
   report quotes the commands and outputs.

Constraints on all steps: no harness spawn, no network (no `cmd/relevo`
tests that execute subcommands reaching herdr — check how existing status
tests fake it first); no `#NNN` in code or comments; test names say what
they pin; new commits only.

Machine-scoped human output. Nothing else.
