# Cockpit A2, round 2: the migration to actors, and actors become the config

Round 1 (commit `79a509a`) is on this branch. It adds `internal/actors`, the registry's
`off` flag, and `config.Load`'s preference for an `actors` section. It was verified.
The A2 plan is appended for context. Its round-2 row is:

> The one-time migration from `roles` or legacy to `actors` + `agents`, recorded as
> a `migration` revision. The `roles` section, `policy.order`, `policy.tier` and
> `candidate.roles` stop being read. `config init` seeds actors. `roles-init` goes.
> `relevo config` prints an `actors` block.

This section is the detailed round-2 plan. Line numbers are as on `cockpit/wave-1`;
round 1 shifted a few in `internal/roles` and `internal/relevo/candidate.go`, so find
those sites by function name.

**If a step is impossible as written or contradicts the code, stop and report. Do not
improvise.** CI has no harness and no network. Everything here is config, registry
and text, tested without spawning anything. `cmd/relevo` tests run `config`
subcommands in-process under `initRoot(t)`.

**Output rule for every text change in this round:** plain text only. Never write ANSI
escape sequences in `internal/relevo` or `cmd/relevo` output. `relevo config` is read
by planners through a pipe.

## R3. The migration: `(*config.Store).MigrateToActors() (bool, error)` (new, `internal/config/migrate_actors.go`)

**When:** the stored config has **no** `actors` section **and** has at least one of:

- a `roles` section;
- `order` or `tier` in `policy`;
- a `roles` or `tier` key on any candidate.

Otherwise return `false, nil`. A fresh install with none of these is seeded by
`config init` (R5), not by the migration.

**What it computes, a pure function**
`migrateDoc(doc Doc, set *candidate.Set) (out Doc, notes []string, err error)`:

1. Build the old registry exactly as `Load` does today:
   `roles.Build(rolesFile-or-nil, set, policy)`. With no roles section this is
   legacy mode. Then take `f, _, err := roles.FromLegacy(set, pol)`
   (`internal/roles/init.go:27`), which gives every builtin row with its ranked
   tokens, unlisted candidates appended, and its tier. In file mode, use the stored
   roles `File` itself.
2. For each role name in `reg.Names()` (builtins first, then custom), in that order,
   write one actor:
   - **Agent:**
     - If the role's `Definitions`, for every kind in `harness.All()`, equal the
       shipped builtin's (`Agent` and `Requires`), use the shipped agent name:
       `plan-executor` for builder, `reviewer`, `researcher`.
     - Otherwise it is a `native` agent. Name it after the role's claude
       definition's agent when every kind uses the same agent and requires,
       otherwise `<role>-agent`. Its `native` map is the role's definitions for the
       kinds that have one, and its `shape` is the role's shape.
     - If that name collides with a shipped agent name or an existing agents key,
       use `<role>-agent`.
     - Note each native agent created: `agent <g>: from role <r>'s definitions`.
   - **Candidates:**
     - Legacy mode: the ranked tokens (`Ranked[].Token`), including unlisted ones.
     - File mode: the row's `Candidates`, as written.
     - Each token that resolves in `set` is written as its **name** (`set.NameOf`).
       One that does not resolve is kept as written, with a note:
       `actor <r>: candidate "<t>" is not configured; kept`.
   - **Tier:** `reg.RoleTier(name)` when set.
   - **Check:** in file mode, the row's `Gate` when set. In legacy mode, nil.
   - **A builtin role with no candidates** still becomes an actor, with an empty
     list, so its agent stays visible.
3. `out` is `doc` with:
   - `actors` and `agents` (the latter only when non-empty), encoded with
     `actors.EncodeActors` / `EncodeAgents`;
   - `roles` **removed**;
   - `policy` with its `order` and `tier` keys removed. Edit the decoded
     `map[string]json.RawMessage` so every other key and its bytes survive;
   - `candidates` with each element's `roles` and `tier` keys removed. The same
     per-element map edit: `name` and every other key survive. A candidate `tier`
     that differed from its role's tier cannot be expressed on an actor, so note
     it: `candidate <n>: tier <t> dropped; set it on the actor`.

**What it writes:** one Tx, through the same commit path `PutDoc` uses (A3a's
`record`):

- `ConfigPut` for `actors`, `agents` (if any), `policy` and `candidates`;
- `ConfigDelete` for `roles`;
- one revision with source `migration` and message `roles → actors`, plus
  `; ` and the notes joined by `; ` when there are any.

Every section of `out` must pass `Validate` before the Tx starts. A failure aborts
with nothing written.

**The equivalence rule, pinned by a test:** for every actor name `a` and every kind
`k` in `harness.All()`, the registry `Load` builds **after** the migration must give
the same `Spec(a, k)` (error or not), the same `Ranked` tokens in the same order,
and the same `RoleTier(a)` as the registry before it. The one exception is legacy
`Position 0` ("unlisted") entries, which become ordinary positions.

**Callers:**

- `newRuntime` (`cmd/relevo/main.go`), right after `EnsureCandidateNames` and under
  the same `!d.Newer()` guard: call `MigrateToActors`. When it returns true,
  `slog.Info("config: roles migrated to actors (relevo config log)")`. An error is
  `slog.Warn`, and the old config keeps working.
- Serve `loadConfig` (`cmd/relevo/serve.go`), under the same guard.

The migration never touches a round. Picks are the same before and after, by the
equivalence rule, so it needs no "no round open" guard.

## R4. After the migration, the old keys are not read

- `config.Load`: with `actors` present, a `roles` section, `policy.order`,
  `policy.tier`, or a candidate's `roles` or `tier` produce the warning
  `config: <what> is ignored; actors decide (relevo config log shows the migration)`,
  and are not used.
  - `roles`: round 1 already ignores and warns. Extend the same path to the other
    three.
  - The registry is built from actors only.
  - `candidate.Parse` still **accepts** those keys, so an old snapshot rolls back
    cleanly and `ImportFiles` of an old `~/.config/relevo` still imports.
- Rolling back to a pre-migration revision is allowed. It restores `roles` and
  removes `actors`, and the next `newRuntime` migrates again, as a new revision.
  Pin that with a test.

## R7. `relevo config` prints an actors block (`cmd/relevo/config.go` `configShow`, `:95-115`)

- The first block's heading becomes `actors`, and its body is a new
  `relevo.FormatActors(L config.Loaded, reg *roles.Registry) string` in
  `internal/relevo/actors_list.go`. The format, plain text:

  ```
  builder  plan-executor  writer  shipped  tier yolo  check on
    candidates  deepseek-v4.1-flash, gpt-5.6-terra, gemini-3.8-flash-high (off), sonnet
  reviewer  reviewer  reader  shipped  tier yolo
    candidates  sonnet, gpt-5.6-terra
  designer  ui-designer  reader  custom  tier -
    candidates  claude-sonnet-4-6
  ```

  Then, only when `agents` is non-empty, a line `agents`, followed by one line per
  custom or native agent:
  `  ui-designer  reader  output design  kinds claude, agy` or
  `  my-exec  writer  native  kinds claude`.
- With no actors (a legacy config that has not migrated, which only happens with a
  newer schema), keep today's `FormatRoles` block under the heading `roles`.
- The `pick` and `candidates` blocks are unchanged.
- **Tests:** update `TestConfigBareShowsThreeHeadings` (`config_test.go:53`) to
  expect `actors`. Add `TestFormatActors`: shipped, off, custom and native entries,

## Working efficiently

A builder pays one round trip per step whatever the step does, so:

- Batch the reads:
  - `internal/roles/{registry,init,file}.go`
  - `internal/actors/*.go`
  - `internal/config/{config,names,revision}.go`
  - `internal/setup/setup.go`
  - `cmd/relevo/{init,roles,config}.go`
  - `internal/relevo/{roles_list,policy_view}.go`
  - the R2 sites
- R2's replacement is mechanical: do it in one scripted pass
  (`perl -pi -e` over the listed files), then fix the texts by hand.
- Iterate on
  `go test ./internal/roles/... ./internal/actors/... ./internal/config/... ./internal/relevo/... ./cmd/relevo/ -run 'Init|Config|Roles'`.
- Run `make check` once at the end.
- Report:
  - the functions with their line ranges;
  - the notes the migration produces for this repo's `internal/roles/testdata` legacy
    fixtures;
  - `git diff --stat`.
