## Settled design

### Roles and colour fields (the converter's output shape)

`parseMermaidToExcalidraw(text, cfg)` returns `{elements, files?}` — **element skeletons**, not scene elements. For `flowchart TD` the shape is: one `rectangle`/`ellipse`/`diamond` skeleton per vertex with `{id, label:{text,fontSize,verticalAlign}, x, y, width, height, strokeWidth:2, groupIds, roundness?, link?}`; one `rectangle` skeleton per subgraph, **pushed first**, with `id` absent, `groupIds:["subgraph_group_<id>"]` and `label.verticalAlign:"top"`; one `arrow` skeleton per edge with `{id:"<start>_<end>", groupIds, x, y, points, strokeWidth, strokeStyle?, label?, start:{id}, end:{id}, roundness}`. `files` is present only for the unsupported-diagram fallback (`graphImage`), whose one `image` skeleton carries `fileId`.

The skeleton list is **one entry per converter descriptor, in the converter's own order** (measured: `G, A, B, C, D, A_B, B_C, B_D` for the fixture; ids match 1:1 with the descriptors `parseMermaid` produced). The evidence script asserts this invariant, so a converter bump cannot break it silently.

**Role heuristic** (`board/src/mermaid.js`, pure, no DOM):
- **cluster** — the skeleton's `id` is absent **or** is a member of the last descriptor's `groupIds` (the subgraph pass runs first and builds `subgraph_group_<id>`); this is the measured signature, not a name guess.
- **edge** — `type` is `arrow` or `line`.
- **node** — `type` is `rectangle`, `ellipse` or `diamond`.
- **other** — everything else (`text`, `image`). `other` keeps its colours and its `fileId`; its `files` entry is carried through.

The fields that carry the colours, from the theme object the server sent as `doc.theme`:

| role | `strokeColor` | `backgroundColor` | `fillStyle` |
|---|---|---|---|
| node | `theme.ink` | `theme.panel` | `solid` (as the converter already sets where it fills) |
| edge | `theme.line` | `transparent` | unchanged |
| cluster | `theme.line` | `theme.faint` | `solid` |
| other | unchanged | unchanged | unchanged |

Label text needs no pass: `convertToExcalidrawElements` binds each label with `strokeColor: label.strokeColor || container.strokeColor`, so node labels inherit `theme.ink` and cluster labels `theme.line` from the container we coloured.

> Note the seed's "cluster → faint" is the **fill** here, with `theme.line` as the cluster outline. `faint` as a fill with no border would leave the subgraph's box invisible against `bg`; the report says this reading is the one taken and why.

### `themeVariables`, field by field (the same palette table)

| mermaid variable | theme field | why |
|---|---|---|
| `background` | `bg` | the canvas behind the rendered diagram |
| `primaryColor` | `panel` | node fill |
| `primaryBorderColor` | `ink` | node outline |
| `primaryTextColor` | `ink` | node label |
| `mainBkg` | `panel` | alias mermaid reads for the node fill in other diagram types |
| `nodeBorder` | `ink` | alias for the node outline |
| `secondaryColor` | `panel` | sequence/state secondary fill |
| `tertiaryColor` | `panel` | cluster-ish fallback fill in other diagram types |
| `lineColor` | `line` | edges and actor lifelines |
| `textColor` | `ink` | edge labels and plain text |
| `clusterBkg` | `faint` | subgraph fill |
| `clusterBorder` | `line` | subgraph outline |
| `fontFamily` | `"Cascadia"` | keeps the rendered diagram on the theme font (`theme.go`'s `FontFamily` 3 is Cascadia) |

`fontSize` is **left to m2e**, which forces `fontSize * 1.25` in `parseMermaid` and uses the un-multiplied size for the Excalidraw elements.

### UI and flow (`board/src/index.jsx`)

- A `Mermaid` toggle in the bar (`data-testid="mermaid-toggle"`) opens a panel under the bar: textarea (`data-testid="mermaid-text"`, no file input — there is **no companion `.mermaid` file in S3**), `Render` (`data-testid="mermaid-render"`), `Import` (`data-testid="mermaid-import"`), preview (`data-testid="mermaid-preview"`).
- **Render** with empty text: preview reads `nothing to render`. Otherwise it awaits `convert(text, doc.theme)` and shows the diagram's structure as text, one line per element: `role<TAB>id<TAB>text`. **Invalid Mermaid:** the preview reads `mermaid: <first line of the error>`, the scene is untouched, nothing is dirty. `Render` never touches the canvas.
- **Import** with empty text: notice `nothing to import`. Otherwise it awaits `convert`, offsets the result and calls `api.updateScene({elements: [...api.getSceneElements(), ...converted.elements], captureUpdate: "NEVER"})`, then `api.addFiles(Object.values(converted.files))` when files exist. **Existing elements are never replaced:** the append keeps every existing element object with its id, and `captureUpdate:"NEVER"` keeps Excalidraw's undo history as the user left it. On success: notice `imported N elements`, `dirty` true. **Invalid Mermaid:** the catch puts `mermaid: <first line>` in the bar notice, leaves the scene, the dirty flag and the textarea alone, and never clears the scene.
- **Offset (`board/src/import.js`).** The same rule S2 uses for `annotate`: `dx = (existing empty ? 0 : min(existing x)) - diagramMinX`, `dy = (existing empty ? 0 : max(existing y + height) + 20) - diagramMinY`, applied by adding `dx`/`dy` to each element's `x`/`y` (linear elements carry relative `points`, so the origin moves the whole arrow). A second import therefore stacks visibly below the first instead of overlapping it.
- **Repeatability/ids.** `parseMermaidToExcalidraw`'s skeleton ids are the Mermaid names (`A`, `B`, `A_B`) and its `image` fileId is a nanoid; we never reuse either. `convertToExcalidrawElements(skeletons)` regenerates every id (`regenerateIds !== false` in 0.18.1), so two imports of the same text can neither collide nor replace, and their ids differ. The page holds no id state and stores none on the scene, so `Save` writes whatever the canvas holds.
- **Error-path hygiene.** `parseMermaid` appends a hidden `#mermaid-diagram` div to `document.body` and removes it only on success (`dist/parseMermaid.js`, `svgContainer.remove()`), so `convert` removes any `#mermaid-diagram` node in a `finally`.

### CSP and network

**No CSP change.** Section 7's string still covers the page: everything is bundled, styles are inline (`style-src 'unsafe-inline'`), the subsetter worker is already allowed. **No new runtime network:** no CDN, no fetch, no `https://` in `board/src/**` (guarded by S3.1 below); the only requests stay `GET /assets/*` and `/api/scene`. The browser check confirms it in devtools.
