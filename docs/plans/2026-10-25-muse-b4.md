# Plan B4 of #1380: the sandbox code reaches every verb (correction round)

B1-B3 are committed on this branch. A real run in an env sandbox, from inside
muse's default sandbox, showed B1 does not reach the user:

```
$ relevo status; echo EXIT=$?
relevo: internal: relevo owner unavailable: db: dial /…/relevo.sock: open failed: relevo owner socket denied by the sandbox: /…/relevo.sock: dial unix /…/relevo.sock: socket: operation not permitted
  next: relevo bugreport
EXIT=1
```

The classification is right (muse's sandbox gives EPERM, and the chain carries
`errOwnerSandboxDenied`), but `status` -- like most verbs -- turns a
`newRuntime()` failure into `fail(codeInternal, "%v", err)` directly
(`cmd/relevo/status.go:154`, `:293`, `:364`, and about 80 more call sites across
`cmd/relevo`), never reaching `writeError`. `fail` formats with `%v`, so the
chain is gone.

Read CLAUDE.md's code-style rules before editing (70-line functions, comments
say why, no history in code, test names say what they pin; no `cmd/relevo` test
spawns a harness or reaches the network).

## Behaviour

1. **One central rule, no call-site edits.** In `cmd/relevo/clierror.go`, a
   failure built with code `internal` (through `fail`, `failNext` and
   `failWrap`) whose arguments or cause include an error matching
   `errOwnerSandboxDenied` (`errors.Is`) is built as `owner_sandbox_denied`
   instead, with that code's catalog `next`. Put the decision in a pure helper
   (e.g. `sandboxCode(code errorCode, args []any) errorCode`) and call it from
   the constructors. Every other code, and `internal` without the sentinel, is
   unchanged. Do not touch the ~86 call sites.
2. **Fail fast on a denial.** In `dialWithStart` (`cmd/relevo/machinedb_unix.go`),
   when the first dial is a sandbox denial, return the sandbox error at once:
   do not call `daemonStarter` and do not spend the retry budget. A denial
   never resolves by waiting, and starting a daemon from a sandboxed shell is
   pointless. Missing and refused sockets keep today's start-and-retry path.
   Check `openDBRoute`'s `awaitStartingOwner` path too: a sandbox denial must
   not wait there either.
3. **Distinct doctor row names.** The muse plugin rows from B2 reuse the Claude
   rows' names, so `relevo doctor` prints two rows named `plugin`, two `plugin
   hook` and two `plugin version`. Name the muse ones `muse plugin`, `muse
   plugin hook` and `muse plugin version`. Update the tests that pin them.

## Tests

- `TestFailReclassifiesSandboxDeniedInternal`: `fail(codeInternal, "%v", e)`
  with `e` wrapping `errOwnerSandboxDenied` (wrapped twice, the way the real
  path does: `errOwnerUnavailable` around `db.ErrOpen` around it) yields code
  `owner_sandbox_denied` and its catalog next; the same with a plain error stays
  `internal` with `relevo bugreport`; `fail(codeUsage, …, e)` stays `usage`.
- `TestStatusOnSandboxDeniedOwnerPrintsSandboxCode` or the nearest pure
  equivalent: the error `status` produces from a `newRuntime` failure carrying
  the sentinel is classified `owner_sandbox_denied`. If `status` cannot be run
  in a test without a daemon, pin it through the constructor test above and say
  so in the report.
- `TestDialWithStartReturnsAtOnceOnSandboxDenial`: with an injected first-dial
  error that is EPERM, `dialWithStart` returns the sandbox error without calling
  the daemon starter (fake it) and well inside the budget; an ENOENT first
  dial still calls the starter.
- The doctor row-name tests updated to the `muse plugin*` names.

Mutation-check behaviour 1 yourself (drop the reclassification) and name the
test that fails.

## Must NOT change

- Any other error code, catalog entry or next hint; the `writeError` arm B1
  added (it stays); missing/refused socket behaviour; the Claude doctor rows.
- Files outside `cmd/relevo/clierror.go`, `cmd/relevo/machinedb*.go`, the doctor
  muse rows and their tests, unless a test pinning the old text must change.
