## 3. The tool

- Run it from the repo root: `~/.cache/relevo-verify/parallelize/parallelize [-n] [-skip A,B] ./internal/<pkg>`.
- `-n` is a dry run that prints `parallel: N  sequential: M` and one `seq <Test>  <reason>` line per sequential test.
- Without `-n` it edits the package's `*_test.go` files in place.
- To re-run it on a package, first `git checkout -- internal/<pkg>/*_test.go`. Never do that for `internal/relevo`.

## 4. Contract

- **Diff shape:** the diff has only `+\tt.Parallel()` lines and blank `+` lines, in `_test.go` files of the three
  packages.
- **Stability:** for each package, `go test -race -count=1 -cpu 4 ./internal/<pkg>` passes three times in three
  separate invocations. `go test -race -count=1 ./internal/<pkg>` (all cores) passes twice.
- **Timing:** report each package's `-cpu 4` time next to its base time from §1.

## 5. Handling a failure

When a test fails or a `DATA RACE` appears in the modified tree:
1. Check whether it reproduces on the base code with a `-count=1` run. Round 1's overlay method works: substitute the
   base copies of the package's `_test.go` files with `go test -overlay`, without touching the tree.
2. If it reproduces on base, it is pre-existing. Record it and continue.
3. If it does not reproduce on base, and the package is `internal/stats` or `internal/config`: add the test, and for a
   race both named tests, to `-skip`. Restore that package's files and re-run the tool.
4. If it does not reproduce on base and the package is `internal/relevo`: remove that test's inserted `t.Parallel()`
   line and the blank line after it by hand, with one edit per test. This is the only allowed hand edit.

Never change an assertion, a helper, or production code.

Stop and report if more than 25 tests need skipping in one package.

## 8. Working efficiently

A model step costs a round trip no matter what it does, so:
- **Nothing to read up front.** The tool locates everything.
- **Foreground.** Run every test command in the foreground and wait for it. These take minutes. Never background them
  or end your turn while they run.
- **Filter.** Pipe long test output through
  `grep -E '^(--- FAIL|FAIL|ok|panic)|DATA RACE' -A3`.
- **Final check:**
  - `gofmt -l internal/relevo internal/stats internal/config` must print nothing.
  - `go vet ./internal/relevo ./internal/stats ./internal/config`.
  - `sh scripts/check-comments.sh`.
  - `make check` in the foreground.
  - If `make check` cannot run in this environment, say so, run the pieces above, and run
    `go test -race -count=1 -cover ./...`.
