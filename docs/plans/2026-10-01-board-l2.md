## Behaviour

- `relevo board comments [<file>|--board NAME] [--json]` reads the resolved scene and prints every comment in **scene order** — `id, x, y, text, by, at`. A comment is a text element in `elements[]` whose `customData.relevo.comment` is true. A missing scene is no comments, exit 0, nothing created. `--json` is one compact JSON array (the house shape), `[]` never `null`. Text mode is one tab-separated row per comment; nothing else on stdout.
- `relevo board comment [<file>|--board NAME] --text S [--x X --y Y] [--by B]` appends exactly one comment element; every other byte of the scene is unchanged. Without `--x/--y` it lands below the scene's current bounds. It prints one line, `comment: <id>  <path>`, exit 0. A missing scene is a new scene, created with that one element. Repo and live scopes are both valid under L1's resolution; no daemon, no db in the runtime beyond L1's read-only resolution.
- Flat only: no replies, resolve, delete or thread; the CLI never deletes; `--x`/`--y`/`--by` are the only placement/identity knobs.

## Settled rules (rule + the test that pins it)

1. **Marker and where it lives.** `customData: {"relevo": {"comment": true, "by": "<id|human>", "at": "<RFC3339>"}}` on a `type:"text"` element appended to the top-level `elements` array. It is the only key the writer adds under `relevo`; extra keys inside `customData` or inside `relevo` are ignored by the reader and never rewritten by the writer. `TestCommentElementMarker`, `TestReadCommentsMarkerScope`.
2. **Reading ignores everything but the elements array.** The reader walks `elements` in array order; a `relevo.comment` marker outside `elements` (in `appState`, `files`, or any non-element object) is not a comment; a marker with `comment` absent or false is not a comment whatever else it carries. Pinned by the decoy-marker case in `TestReadCommentsElementOrderAndMarkerScope`.
3. **Malformed markers and non-scenes refuse, they do not guess.** An element carrying `comment:true` that is not `type:"text"`, or whose `by` is missing/empty, or whose `at` is not RFC3339, is `refused` (exit 2) naming the element id; a file that is not a JSON object with `type:"excalidraw"` and an `elements` array is `refused` naming the path. `board.ErrInvalid` maps to `codeRefused` in `boardRefusal`. `TestCommentsRefuseMalformedMarker`, `TestCommentsRefuseNonScene`, `TestBoardCommentRefusalCodes`.
4. **Order is the array, not the clock.** Comments come back in `elements[]` order even when the stored `at` values disagree with it. `TestReadCommentsElementOrderAndMarkerScope`.
5. **The element field set** is the vendored 0.18.1 text element: base fields (`id, type, x, y, width, height, angle, strokeColor, backgroundColor, fillStyle, strokeWidth, strokeStyle, roughness, opacity, groupIds, frameId, index, roundness, seed, version, versionNonce, isDeleted, boundElements, updated, link, locked, customData`) plus `text, fontSize, fontFamily, textAlign, verticalAlign, containerId, originalText, autoResize, lineHeight`. `fontSize` 20, `fontFamily` 3 (reuse `board.FontFamily`), `textAlign "left"`, `verticalAlign "top"`, `roughness` 0, `angle` 0, `opacity` 100, `strokeColor` = the theme's `comment`, `backgroundColor "transparent"`, `updated` = `at` in Unix ms, `seed`/`versionNonce` 0, `version` 1, `index`/`frameId`/`roundness`/`boundElements`/`link` null, `locked`/`isDeleted` false, `groupIds` `[]`. `id` is 20 crypto-random URL-safe chars. `TestTextElementFieldSet`.
6. **Font safety and the estimate.** `autoResize:true`, an explicit `width` ≥ the estimate, `fontFamily:3`, `lineHeight:1.2` (Cascadia's metric in the vendored bundle; `fontSize` 20). `TextSize(text, fontSize)` measures per line: 0.6 em per narrow rune (Cascadia's advance is 1200/2048 ≈ 0.586 em, so 0.6 is a ceiling that never underestimates), 1.0 em for East Asian wide/fullwidth and emoji runes, `ceil` on both dimensions, `height = ceil(lines × fontSize × lineHeight)`; `\r\n`/`\r` normalised to `\n` first. `TestTextSizeEstimate`, `TestTextElementFieldSet`.
7. **Builder location.** `internal/board/element.go`: `TextElement` (typed, JSON tags in the order above), `TextOptions`, `NewTextElement`, `TextSize`. `TextOptions.Marker` is nil for a plain text element, so S2's `annotate` reuses the same builder without the comment layer.
8. **Raw append.** `internal/board/splice.go`: `AppendElement(scene, element []byte) ([]byte, error)` finds the top-level `elements` array's byte span (`json.Decoder` + `InputOffset`, never a whole-document unmarshal), inserts `,` + element before the array's closing `]` (no comma into an empty array) and touches nothing else; a document that is not an object whose `elements` is an array is `ErrInvalid`. `TestAppendElementLeavesTheRestByteIdentical`.
9. **`--by`.** Default: `board.DefaultBy(os.Getenv("RELEVO_MASTERMIND"))` → the env value when set, else `human`; an explicit `--by` wins. Validation in the package: non-empty after trimming, ≤ 64 bytes, no control characters. The *default* value is validated too, so a bogus env is a `usage` refusal (exit 2). `TestByDefaultAndValidation`, `TestBoardCommentByDefaultsToMasterMind`.
10. **`comments --json` shape.** A bare array of objects whose keys are exactly `id, x, y, text, by, at` in that order, one compact line via `json.NewEncoder(os.Stdout)`; zero comments is `[]`. `TestBoardCommentsJSONShape`.
11. **Placement.** With no `--x/--y`: bounds over the scene's non-deleted elements' `x, y, width, height` (missing numbers 0); `x = min x`, `y = max y + commentGap` (`commentGap = 40`); an empty scene is `(0,0)`, so an agent's comment never lands on a drawing and consecutive comments stack clear of each other. `TestAddCommentPlacement`.
12. **Missing scene.** `comments` returns nothing and creates nothing (not even the live dir); `comment` writes a fresh scene `{"type":"excalidraw","version":2,"source":"local","elements":[<element>],"appState":{"viewBackgroundColor":"<theme bg>"},"files":{}}` — the appState background is what the page's `isNew` path can no longer supply once the file exists (`board/src/index.jsx:125-129`) — then appends normally. `TestReadCommentsMissingScene`, `TestAddCommentCreatesMissingScene`.
13. **Resolution and the pointer.** Both verbs use L1's `resolveBoard` (`<file>|--board NAME`, ambient `RELEVO_MASTERMIND`, single-registered fallback; `isPeekArgs` already covers any `board …` argv, so no route change). No new `--mastermind` flag (the seed's usage lines omit it): the MasterMind comes from `RELEVO_MASTERMIND`, the single record, or an explicit live path. `comments` is read-only and never writes the pointer; `comment` selects like `board` does — on a live board whose name differs it writes the pointer (which also creates the live dir with L1's mode), on a repo board it never touches it. `TestBoardCommentsNeverWritesPointer`, `TestBoardCommentWritesPointer`.
14. **Write path.** `AddComment` writes through S1's atomic temp+rename (`internal/board/scene.go:114-141`), so an interrupted write leaves the old scene; no etag/CAS (the CLI append is not the page's `If-Match` path); no other file is written.
