## Behaviour and cases

1. **Text step-aside.** Plain `relevo status --line` (no `--json`) prints the MasterMind line and the board line, then **no binding rows**, while THIS mastermind's push claim is live. Without a live claim it prints byte-identical output to today.
2. **`--line --json` unaffected.** It keeps every row (band + OpenCode sidebar read it) and gains `push_live`.
3. **Additive fields only.**
   - `StatusLineDoc.push_live` (bool, always present, no omitempty): this mastermind's push claim is live, from the same claim read `mastermindRoute` uses.
   - `StatusLineRow.activity` (string, omitempty): **single field carrying `ActivityWord` verbatim** (`working`, `quiet 2m`, `stalled 17m`, `exploring 7m`, `gating …`, `exited N`, `running`, `queued (…)`; absent when `ActivityWord` is `""`). No `activity_age`: the age rides inside the word exactly where the existing text shows one, and splitting would add parsing with no consumer — this is the "say which" decision.
   - `StatusLineRow.chain_progress` (object, omitempty, only on a chain's stand-in row): `{done, total, phase}` derived from the same `ChainFacts` the `Chain` string renders from (`Plan`/`Plans` + `Step` on fixed chains, `PlanPos`/`PlanTotal` + `StepAt` on flow chains; builder pins the mapping for both). `Chain` stays.
4. Existing JSON keys, text goldens of other consumers, and the OpenCode plugin's reads keep working.
