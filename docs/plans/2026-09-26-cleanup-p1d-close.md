## 1. System overview

Two things close phase 1. First, delete the functions no longer reachable from
the `relevo` binary now that the deletion rounds have landed. Second, record
per-package statement coverage as a baseline and make `make check` fail when a
package drops more than one point below it -- this is what guards phases 2 and
3, which move and shrink code and tests.

## 3. Deletion list (closed)

**D10 -- dead code.** Run, from the repo root:

```
go run golang.org/x/tools/cmd/deadcode@latest -test ./... > /tmp/dead-test.txt
go run golang.org/x/tools/cmd/deadcode@latest -test -tags jev ./... > /tmp/dead-jev.txt
```

`-test` makes test functions roots too, so a function only tests reach is
**not** reported and survives (spec: functions only tests or build-tagged code
reach are kept). Delete exactly the functions reported by **both** runs (the
intersection keeps anything the `jev` build tag reaches). Exceptions, kept even
if reported:
- anything in `internal/legacy`, `internal/migrate`, or `cmd/relevo/migrate.go`
  (relay->relevo migration is kept until #411);
- methods that satisfy an interface through reflection or registration the
  tool cannot see (for example `json.Marshaler`, `flag.Value`, `sort.Interface`,
  `error`, `fmt.Stringer`, `tea.Model` methods) -- deadcode normally sees these,
  but if one is reported, keep it and list it.

After deleting, run both commands again: repeat until the intersection is
empty (deleting a function can make its only callee dead), at most 3 passes;
list what each pass removed.

## 4. Coverage guard: formats and contracts

**Coverage output.** `make check`'s test step becomes
`go test -race -count=1 -cover ./...` with its combined output also written to
`.coverage.txt` in the repo root (gitignored), and `make check` still fails when
the tests fail. Use a form that preserves the test command's exit status under
POSIX `sh` (no `pipefail`), for example writing to the file, then printing it,
then exiting with the saved status.

**`testdata/coverage-baseline.txt`**: one line per package with test files,
`<import path> <percent with one decimal>`, sorted by import path, e.g.
`github.com/fuad-daoud/relevo/internal/db 71.3`. Packages reported as
`[no test files]` are absent. Generated by the script (below), never by hand.

**`scripts/check-coverage.sh [--write] [FILE]`** (POSIX `sh`, shellcheck-clean):
- Reads a `go test -cover` output file (`FILE`, default `.coverage.txt`) and
  extracts `ok  <pkg>  <time>  coverage: <pct>% of statements` lines.
- Without `--write`: for each package in the baseline that appears in the
  output, fail if `pct < baseline - 1.0`, printing
  `<pkg>: coverage <pct>% is below baseline <base>% (-1.0 allowed)`. A package in
  the output but not the baseline prints `<pkg>: not in baseline (new package?)`
  and does not fail. A baseline package missing from the output prints a note
  and does not fail (it may have been deleted or merged). Exit 1 on any failure.
- With `--write`: rewrite `testdata/coverage-baseline.txt` from `FILE`.
- If `FILE` does not exist: print `check-coverage: no coverage output (run make check)`
  and exit 1.

**Makefile.** `check` runs `sh scripts/check-coverage.sh` after the test step.
The existing loop over `scripts/*_test.sh` picks up the new test script.

**CLAUDE.md**, in `### Code style`, one bullet: `make check` also fails when a
package's statement coverage drops more than one point below
`testdata/coverage-baseline.txt`; a round that moves code between packages
regenerates the baseline with `sh scripts/check-coverage.sh --write` and says
so in its report, and no round lowers a baseline to get green.

## 5. Pseudocode

```
D10:   loop up to 3: dead := run(-test) ∩ run(-test -tags jev) − exceptions
                     if dead empty: break; delete dead; go build ./... && go vet ./...
cover: make check (writes .coverage.txt)                      # on the post-D10 tree
       sh scripts/check-coverage.sh --write                   # baseline from it
       sh scripts/check-coverage.sh                           # must pass
       run make check twice more; the guard must pass both times
```

## 6. Error handling

- If a package's coverage differs by more than 1.0 point between two
  `make check` runs on an unchanged tree (flaky coverage), do not widen the
  tolerance: list the package and both values in the report, and stop.
- If `deadcode` cannot be fetched (no network), stop and report.

## 7. Working efficiently

- Run both deadcode commands once, diff them, then read every reported function
  in one batch before deleting.
- Each file's edits in one edit call.
- Focused loop: `go build ./... && go vet ./...`, then
  `go test ./<touched packages> -count=1`; for the script,
  `sh scripts/check-coverage_test.sh` and `shellcheck scripts/check-coverage*.sh`.
- `make check` is slow (race tests over the module); run it only in steps 4-5.

## 8. Ordered steps

1. D10, pass 1-3. Build, vet and the touched packages' tests pass after each pass.
2. `scripts/check-coverage.sh` + its test script and fixtures (a passing output,
   a regression of 1.5 points, a new package, a missing file). Test script passes.
3. Makefile (coverage output, guard step), `.gitignore`, CLAUDE.md bullet.
4. `make check`, then `sh scripts/check-coverage.sh --write`, then `make check`
   again twice: both must pass, and the second and third runs must not differ
   from the baseline by more than 1.0 in any package (§6).
5. **Mutation check.** Delete one test function from a small package (for
   example the only test of a formatter), run `make check`, confirm the guard
   fails naming that package, restore the test.
6. `git diff --stat` shows only §2 files and D10's files. Commit.
7. **Save the plan.** Copy this plan to
   `docs/plans/2026-09-26-cleanup-p1d-close.md` and commit it.

Report: the functions deleted per deadcode pass (file:function), anything kept
under the exceptions, the baseline's package count and its lowest five
packages, the three runs' maximum per-package difference, and the mutation check.

# Cleanup P1d (round 2) -- tie the coverage baseline to the environment it was measured in

Round 2 of `cl-p1-close`. Round 1 (commits `f63ae93`, `e1953b7`, PR #522) added
`scripts/check-coverage.sh` and `testdata/coverage-baseline.txt`. CI failed:

- `check (ubuntu-latest, go 1.25)`: 16 packages 1-5 points below the baseline

  Go 1.25 counts statements differently from the Go 1.27 that measured the

  Linux-only paths (cgroups, scopes) do not run on darwin.
- `check (ubuntu-latest, go stable)`: passed -- the same environment as the baseline.

### 1. Contract changes

**Baseline header.** `testdata/coverage-baseline.txt` gets a first line
`# measured with go<major>.<minor> <GOOS>/<GOARCH>` (for example
`# measured with go1.27 linux/amd64`), taken from `go env GOVERSION` (trimmed to
major.minor, ignoring any `-X...` suffix and patch) and `go env GOOS GOARCH`.
`--write` writes it. The package lines are unchanged.

**`scripts/check-coverage.sh` (without `--write`):**
- Read the header. Compute the same string for the running toolchain.
- If they match: compare as today.
- If they differ and `RELEVO_REQUIRE_COVERAGE=1`: print
  `check-coverage: baseline was measured with <header>, this is <current>; regenerate it with --write on <header's env or the CI leg>`
  and exit 1.
- If they differ otherwise: print
  `check-coverage: skipped (baseline measured with <header>, this is <current>)`
  and exit 0.
- A baseline with no header is an error (exit 1) with a message saying to
  regenerate it.

**CI** (`.github/workflows/ci.yml`, job `check`): set
`RELEVO_REQUIRE_COVERAGE: '1'` on the ubuntu-latest / go stable leg only, using
the same expression style as the existing `RELEVO_REQUIRE_LINT`.

**CLAUDE.md**: extend the existing coverage bullet by one sentence: the baseline
is tied to the Go minor version and platform in its header, is enforced on CI's
ubuntu/stable leg, and is skipped elsewhere; a Go upgrade on that leg means
regenerating it.
